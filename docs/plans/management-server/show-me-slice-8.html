Delivered

What now works. A new organisation goes from sign-up to a working npm install through a managed firewall, in one scripted test. An operator can install, start and restore the service from the documents.

  • End-to-end test (tests/e2e/signup_to_install.sh): sign-up to npm install done in 1.3 s. The whole script, with both image builds, took 3 min 47 s (target: under 10 minutes).
  • Propagation: 50 policy edits and 50 key revocations reach the firewall with p99 about 5 s (edits 5.049 s, revocations 5.035 s) against a 10 s interval.
  • Both images build (firewall and probation-server) with the label org.opencontainers.image.licenses="Elastic-2.0".
  • Release gate: in .github/workflows/release.yml, both publish and release need the e2e job (C82).
  • Deploy examples and operator docs: deploy/docker-compose.yml, deploy/probation.service, docs/operations.md §13 (proxies, plain HTTP behind TLS, server-down behaviour, backup and restore), docs/management-server.md (images, settings, secrets, first run, commands).
  • probation-server admin after-restore (C129): after a database restore, it moves the change counter above every firewall's cursor, so every firewall resets to the restored data. It writes an audit row.
  • admin bootstrap --config --email (S8-14): the first global admin gets an email sign-in and a one-time set-password link, printed on the console only (single use, 60 minutes, no mail). The admin must still set up an authenticator before /admin (C24). admin reset-link prints a fresh link for a live global admin.
  • [portal] firewall_url (S8-1): the .npmrc and pip.conf lines on the keys page now show the real firewall address. Unset, the FIREWALL placeholder stays.
