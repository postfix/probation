Slice 2 done: managed mode against a fake management server

Managed mode is still unreleased. It ships with slice 8.

Delivered

What works now. A firewall with a [management] section is a managed firewall. Each npm or pip request must carry an API key. npm sends it as Bearer <key>. pip sends it as the password of Basic, with any user name. The firewall asks the management server about the key once, then keeps the answer in a cache. Each request is decided under that key's own policy: the policy layers from the platform down to the key's own place.

  • No key, or a key the server does not know (also revoked or suspended): 401.
  • The firewall cannot check the key right now (lookup budget spent, or the server is busy): 503 LOOKUP_BUSY, with Retry-After: 1. A valid key is never told it is wrong.
  • Caches never mix policies. A listing cached for one policy is not reused for a key with another policy.
  • Downloads are decided per key. When two keys wait for the same download, each one gets the answer of its own policy.
  • The API key and its hash never appear in a log line or in a Decision record. The record gains place (C107).
  • The standalone firewall is unchanged.

Request flow (Slice 2)

Contract on this flow: authenticate-checks-retired-first. The "retired" check runs before anything else. The flag is set from slice 3 (C72).

pub async fn authenticate(
    &self,

    // also: key_id (for activity rows), account and rate_limit (C28, C66), org

Limits

  • Managed mode is not released before slice 8. The management server here is a test fake (tests/common/mod.rs).
  • Temporary until slice 3: no sync loop, no network lock, no activity rows and no rate limit. The local blocklist file is still required. An expired cache entry is not served stale: if the server is down, the key gets 401. /health/ready reports not ready.
  • The per-client lookup allowance is keyed by the full client address. A client that changes addresses inside one IPv6 /64 can use up the budget. Moved to slice 3 (S2-2).
  • The sync client cannot use an egress proxy (S2-6). A site that reaches the management server only through a proxy cannot use managed mode. This goes into docs/operations.md in slice 8.
  • The --managed throughput benchmark is noisy on this shared machine (S2-4).
  • Nothing is committed yet: slices 1 and 2 are uncommitted on main.
