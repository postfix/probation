Delivered

What now works. A global admin runs the whole service from the portal. An org admin can drive blocklists from a script.

  • Global admin pages (/admin): organisations (suspend, re-activate, open as org admin), personal accounts (suspend, revoke keys, reset authenticator, delete, restore), global admins (invite, remove; the last one cannot be removed), the platform policy, limits, and IP ranges (approve or refuse). A suspended organisation or account shows a banner, and its keys stop working within one sync interval.
  • Fleet pages (/fleet): register a firewall (its token is shown once), see health in words ("Unhealthy: missed 3 check-ins"), push settings in staggered rollouts, and retire a firewall (you type its name).
  • Automation tokens: an org admin (or a global admin for the platform) creates a token. A script uses it on /api/v1/blocklist/{layer}. The token can change only the blocks of its layer, and it works only while its creator still holds the admin role.
  • Blocklists: import, export and push in the blocklist file format. Each block may carry a reason. A policy without reasons keeps its old fingerprint, byte for byte.
  • Retention: the global admin sets how many days Activity (default 90) and the audit log (default 365) are kept, from 7 to 36500 days. The prune jobs run.

Review fixes (9, all with tests)

  1. Token creator check (B1): an automation token works only while its creator is still an org admin of that organisation, or a global admin. The check runs at every use.
  2. Login erase after range approval (M1): the purge can now erase a global admin who approved a range or sent an invitation. The range stays approved.
  3. Overlapping rollouts refused (M2): a push to a firewall still in another rollout is refused, and nothing is written.
  4. Resume only after a timeout (M3): a failed step offers Skip only; the page says to push corrected settings.
  5. A removed admin's invitations (M4): removing a global admin deletes their open global-admin links, and a link works only while its sender is a live global admin.
  6. Retention cap (M5): at most 36500 days, in the form and in the database. The activity and audit prunes run independently.
  7. Blocklist caps (M6): 5000 records per file, 256 bytes per reason, 5000 blocks per layer.
  8. Limits form (minor): "no limit" stays blank and is not saved as 0; "Set own limits" starts from the organisation default.
  9. Period clamp (minor): the server takes a reported check-in period as at most 86400 s, so health and rollout timeouts still work.

Differences from the mockups

  • Fleet settings are one TOML text box ("Settings, as lines of the firewall's config.toml"), not one field per setting.
  • Retention is set for the platform on /admin. Per-organisation overrides exist in the database (S4-11, S7-11), but there is no per-organisation retention screen.
  • Suspend (organisation), Revoke keys and Delete (personal account) open a confirmation page. Retire asks for the typed name. Remove, Re-activate and Make active act on one press.
