## Findings
Evidence class for all: specification gap from design text (not an executed exploit). Line numbers are of 03-program-design.md.

**F1 (High) Meaning of 401/403 differs between the snapshot route and the OSV route.** l.105 defines "explicit authority refusal" as "only 401/403 received over authenticated HTTPS from the bound server identity" and persists it durably. The same server now also answers 401 on `/osv/v1/querybatch` (l.137, T9-7 "401, 403, 404, 413, 429 do not [count as reached]") with the same credential. The design never says the OSV route's 401/403 are excluded from the refusal rule. Trigger: a service key rotated or a firewall token revoked, or a proxy in front of the server returning 401 on /osv only. Actual per design: ambiguous; one reading makes an OSV 401 a durable policy refusal (outage of all artifact delivery until operator reset), the other makes a real refusal go unnoticed. C1021 also says the key "authenticates only policy retrieval", which C1030 now contradicts (key sent per OSV request by `batcher::send`). Fix: state that persisted refusal is derived only from the snapshot route; OSV 401/403 only mark OSV unreached; amend C1021 wording; test `osv_401_never_creates_or_clears_refusal`.

**F2 (High) "Degraded" is out-of-band and per-batch while the semantics are per-query.** l.141, 157, 158: an upstream failure, invalid, unmapped or over-budget key yields `{}` (the same bytes as a true no-match) and a response header marks degradation. A header is whole-response, cannot say which result is degraded, and is lost to any header-stripping or caching intermediary, in which case a degraded `{}` is a confirmed no-match: it is cached for the negative TTL and, under C1031, "a non-degraded 2xx can replace" a matched entry, so a stripped header erases a known malicious match. Also contradicts "one bad key never fails batch-mates": if one key degrades the batch, the client must either discard good answers for the others or accept the bad ones. Fix: carry degradation per result in the body (an extra field the client reads, osv.dev golden test updated accordingly) or make the client treat any `{}` for a previously matched key as unconfirmed unless an explicit positive per-result "no vulns" marker is present; test header-stripped path.

**F3 (Medium-High) One unknown ecosystem tag stops deny propagation to the whole fleet.** l.105: unsupported tag -> "validation failure retains the last good snapshot with degraded readiness". l.236 adds server tags (maven, go, ...). Trigger: an org adds a Maven registry or a block rule for a new family; every enforcer not yet upgraded rejects the entire snapshot and stops receiving any new deny (including blocks for npm/PyPI). The registry-level isolation rule ("degrades only that registry") is stated only for an absent ID, not for an unknown tag. Fix: unknown tag in a descriptor degrades that registry only; unknown-ecosystem rules in layers are skipped (they cannot apply to a family the enforcer cannot serve) with a counter; keep whole-snapshot rejection only for structural errors. Test: mixed-version snapshot.

**F4 (Medium-High) Credential-bearing-read detection is a deny-list of unnamed representations.** l.125: "Authorization header or the family's native credential", decided "from the request". The shared caches are written when detection says "not credential-bearing". Any missed carrier (Proxy-Authorization, Cookie, `X-NuGet-ApiKey`, `X-JFrog-Art-Api`-style headers, userinfo in a URL, `?token=` query, repeated or differently-cased headers, HTTP/2 pseudo forms) fails open into cross-caller cache sharing, which is the exact confidentiality property C1028 exists for. Fix: invert the default: a request is cache-eligible only if it carries no header outside an explicit allowlist (Host, Accept*, User-Agent, Range, conditional headers) and no userinfo/query secret per family; enumerate per-family carriers in the row 28/17-24 tests (`credential_bearing_read_never_enters_shared_caches` per carrier).

**F5 (Medium) Boundary between "malformed envelope" (4xx) and "invalid key" (`{}`) is undefined.** l.140-141 and l.157 vs test name `osv_route_rejects_unknown_fields_commit_purl_page_token_and_versionless` (l.178) and T9-3 ("unknown fields denied... version required"). A versionless or unknown-field query inside an otherwise valid batch: 400 for the whole batch, or `{}` for that query? The two statements conflict. Impact: one unlisted field from any client version (or any compatible osv.dev client) fails all batch-mates and, per T9-7, counts as OSV unreached. Fix: one table: envelope-level errors (not JSON, wrong top-level shape, oversize body, queries not an array, count over cap) -> 4xx; every per-query defect (unknown field, missing version, bad charset, unlisted ecosystem, over-budget) -> degraded `{}` for that query. Duplicate JSON object keys and duplicate queries in a batch need an explicit rule (reject envelope, one result per query in order, charged once).

**F6 (Medium) Key spelling sent to OSV vs the server's charset/bounds and the real ecosystem spelling.** l.155 "per-field length and charset bounds" are unnumbered and not tied to the l.163-173 table: npm `@scope/name`, Maven `g:a`, Go full module path, NuGet/Conan names, and the version spelling per family (Go `v` prefix, Maven qualifiers, NuGet normalisation, Cargo build metadata, PEP 440 forms) are not specified. A too-strict server charset silently degrades valid names to `{}` (fail-open, invisible except via a counter); a wrong version spelling yields a false no-match from api.osv.dev. Go: the table says "full module path"; it must say the decoded (unescaped) path, never the `!`-escaped proxy form. Fix: add a version-spelling column and a charset per family derived from the same function as `osv_ecosystem`; test valid names for every family go through (not only that bad ones are refused).

**F7 (Medium) Resource bounds for the new recognizers are left to the implementer.** l.178: "Numeric budgets, TTLs, batch and body caps are set by the row 30 implementer and approved with the row (D-OSV3)". Unstated numbers: request body bytes, per-field lengths, JSON nesting, upstream response cap and the endpoint's cap on the server's answer, snapshot size/chain/layer/registry counts (l.105 "bounds", `activation_rejects_invalid_snapshot` "oversized chain"), `Retry-After` maximum (an upstream-controlled value that can hold the breaker open, converting to fleet-wide fail-open), cache entry/byte limits, matches-file per-record size. L7 is therefore established only as a mechanism list, not as bounds. Fix: record concrete numbers (or a rule such as "response cap = 2 x batch cap x per-result bound") in 03 before the rows start; cap `Retry-After`; give a decompression-ratio rule wherever gzip/zlib is accepted (see F13).

**F8 (Medium) No monotonic revision rule on activation.** l.105 fences late replies by config generation only. A lagging replica or retry that returns an older `revision` for the same key and config would be a valid, complete snapshot and could re-activate an older, weaker policy. Fix: activate only when `revision` is >= the active one for the same server/key binding (equal revision must be byte-identical or rejected); test.

**F9 (Medium) Descriptor `target_url` and CIDRs: validated parsed identity, used as resolved address.** l.224 "checked as parsed scheme/host/port/path identity"; l.232 local denylist (loopback, link-local, metadata, own listener). A hostname that resolves or later rebinds to a denied address, alternative IP spellings (decimal/hex/octal, IPv4-mapped IPv6 `::ffff:127.0.0.1`, trailing-dot), userinfo, and redirects are not addressed. The checked value (string) differs from the consumed value (socket address). Fix: parse with a single URL/IP parser, reject userinfo, canonicalise IP literals, and apply the denylist to the resolved socket address at connect time (resolver hook) and on every redirect hop; extend the metadata list beyond 169.254.169.254 (e.g. fd00:ec2::254, 100.100.100.200).

**F10 (Low-Medium) Listener admission details.** l.232: Host validated against `public_url` but comparison rules (port default, case, trailing dot, duplicate Host headers, absolute-form request target, HTTP/2 `:authority`) are unspecified; "/32 IPv6" prefix floor wording is easy to misread as narrowest rather than widest (state it as "prefix length must be at least 32"). Fix: one normalising comparison and tests for duplicates and absolute-form.

**F11 (Medium) Persisted matches file: format undefined, all-or-nothing load, wall-clock expiry.** l.158-159. Record syntax and per-record bounds are not stated; "corrupt ... loads empty": one bad record or trailing garbage discards up to 100000 known malicious matches (only a health warning), which is the C1031 protection loss the design aims to prevent. Expiry persisted as wall-clock time needs clamping to `now + ceiling` at load, otherwise a clock change extends or shortens protection; loaded keys must be re-validated with the same field bounds as the wire. Fix: line-oriented or length-framed records, per-record validation with skip-and-count, whole-file trailing-data rule, clamp on load; test `osv_matches_file_one_bad_record_keeps_the_rest`.

**F12 (Medium) OSV verdict applies to a public namespace, not to the selected registry.** Only Conan is restricted to ConanCenter origin (l.175). Any other family served from a private registry (`target_url` non-public, `trusted`) sends its package names to the central server and api.osv.dev and applies the verdict for the public package of the same name: a false deny for an internal `left-pad@1.3.0`, and private names disclosed to a shared cross-tenant cache (D-OSV2 treats hits as non-sensitive, which holds for public names only). Fix: generalise the Conan rule: query OSV only for keys resolved from a registry whose origin is the ecosystem's public source; record this in the mapping table and add the case to each family row.

**F13 (Low-Medium, outside focus) RubyGems Marshal/gzip.** l.240. Language accepted by the "typed filter" (allowed types, depth, object/link count, size after inflate) is not given in 03, and the filter output is consumed by the client's Marshal.load, a code-capable interpreter, so output must be re-rendered from the typed value, not spliced. Bounds numbers absent (F7). Unreviewed beyond this note.

**F14 (Low-Medium) `osv_generation` ordering is unspecified.** l.123: the counter is incremented "whenever a batch outcome stores" a flipped answer, read inside the gate as an atomic load. Order of "store answer" vs "bump counter" and memory ordering are not given; bump-before-store lets a retry re-read the old no-match and burn the 2-preparation bound into a 503, store-before-bump with a request authorising between them delivers an allow after a match is stored. The gate's write-side linearisation (l.117) does not cover OSV publication. State: store, then bump (release/acquire), and that the residual window is accepted, or bump under the cache lock.

**F15 (Low) Config values as inputs.** `server_url` is used as base for `/api/v1/policy/snapshot` and `<server url>/osv` (l.147) but its form is not constrained (path prefix, trailing slash, userinfo, query, fragment, non-default port): require origin-only, https, no userinfo. `service_key_file`/management token read into a header: bound length, trim a single trailing newline only, reject control characters (header injection) and non-ASCII. Server-side timing: client default 500 ms vs server 300 ms deadline plus connection setup (redirects disabled, fresh TLS) leaves little margin on WAN links; if the upstream batch normally takes more than 300 ms the "degraded" path is the normal path (fail-open in steady state). Unresolved concern, needs a measurement.

**F16 (Low) Temp files for credential-bearing reads are unbounded.** l.125: "request-owned temporary file removed when the response ends" has no cap on concurrent bytes, no orphan sweep after crash/abort, and class R admission is peer-only, so a permitted peer can exhaust disk. Add a per-request and total cap and a startup sweep.

Positive observations (supported by the text, no finding): closed credential set checked before cache read/upstream; request body cannot select a host; URL built by path segments; results length equality enforced before store; failures never cached as confirmed no-match; coalesced waiter cancellation covered; unknown ecosystem rejected through a single shared mapping with an exact-equality test; fixed-order synchronous guards honestly labelled as order-only.
