## New findings
**N17 (Low-Medium) Nested validator and non-Marshal `u:` payloads (LS-F13 B).** The text says the validator recurses into the payload of "every `u:`/`U:` value of an allowed class". Time is allowed and is also `u:`, but its payload is 8 bytes of binary, not a Marshal stream; recursing would refuse a valid gemspec (a function loss), and treating it as opaque is right for Time only. Also unstated: (a) the nested stream's depth must be cumulative with the outer depth (otherwise `u:` inside `u:` inside `u:` resets the 32 limit; the node and byte budgets are shared, so this is bounded but depth is not), (b) the nested stream has its own symbol and link tables and its own `\x04\x08` header, which must be checked, (c) a payload that is not a valid stream is refused. Fix: one sentence per class (Gem::Specification: parse as stream with cumulative depth and fresh tables; Time: fixed binary form plus ivars; others by their form). Test `quick_gemspec_time_payload_not_recursed_and_valid_served`, and `quick_gemspec_nested_depth_is_cumulative`.
**N18 (Low) Reset command and floor reset in a pinned binding.** Fine as written; confirm that `reset-revision-floor` works when the enforcer is not running (offline edit of the cache envelope), otherwise the degraded alert names a command an operator cannot run during an outage. Optional.
**N19 (Low-Medium) Total temp cap acts as a 16 GiB per-request cap, with a transient status (LS-F16).** A single credential-bearing body over `credential_temp_max_total_bytes` (default 16 GiB) is refused with 503 plus Retry-After although the refusal is deterministic, and it is a loss versus streaming before (the round-3 claim "no function lost" holds only below 16 GiB). Fix: refuse a request that alone exceeds the total with a non-retryable status without Retry-After, and either make the total default disk-only or say that 16 GiB is the effective limit (DEFAULT - confirm).
Checked and fine: no nested-Marshal budget bypass in totals (the 4 MiB inflated cap bounds the inner string); reset authority has no network trigger; server held answers cannot erase a match (Matched always honoured); no-cap default has the stated peer-fill residual (accepted in text).
