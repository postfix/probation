Fingerprints (sha256 prefix): osv.rs 53b97451, osv_key.rs 2b66971e, osv_wire.rs 35af11b6, batcher.rs 7419afe3, matches.rs d8ad8460, osv/mod.rs 0a389f83.

## Findings

### SEC-1 Medium (High if the policy has no other signal), confirmed mechanism: unsendable key = silent skip of OSV
Location: crates/probation-policy/src/osv_key.rs:7-9, 24-45; src/osv/batcher.rs (`flush_central`, the `sendable` filter); crates/probation-server/src/osv.rs:425-427; src/pypi/mod.rs:362-378 and src/npm/mod.rs (candidate uses the registry's own version spelling).
Publisher of a malicious package -> chooses a version (npm prerelease or PyPI local version) of 129..256 bytes, or a PyPI name over 256 bytes -> `osv_key` returns Err, the client never sends the key and marks it Degraded; `stale_match` is false -> the candidate is Allowed. Standalone mode would have asked api.osv.dev and matched a `MAL-*` record that uses an "introduced 0" range (the usual shape). So central mode is weaker than standalone, and the attacker chooses whether the check happens. Degraded results are only counted (5% warning), not blocked.
Smallest correction: raise `MAX_VERSION` and `MAX_NAME` to the ecosystems' real maxima (semver 256, npm name 214, PyPI no practical limit: pick 1024 and cap body at the batch cap), or hash/skip nothing. If a key must be refused, make that outcome visible and policy-controlled (hold, not allow) for keys refused only for length. Closure checks: (a) a 200-byte npm prerelease version of a package with a fake MAL record is Matched via the central path; (b) a normal key still works.
Related, Low: legacy npm names containing `!'()*` fail `plain()` (osv_key.rs:31) and fail open the same way; confirm whether the npm adapter admits them.

### SEC-2 Medium, plausible: a follower inherits a foreign leader's deadline and failure (cross-tenant degradation of a chosen key)
Location: crates/probation-server/src/osv.rs:441-459 (follower joins `inflight` before the cache check), 460-463 and 503-507 (`fetch` is timed by the leader's `deadline_at`), 477 (a Failed leader answer is handed to every follower).
Any valid credential holder -> sends a 1000-key batch (slow upstream, longer than the 300 ms server deadline) that contains the keys a victim is about to ask -> victim's request becomes a follower, waits only until the attacker's deadline, then gets `Answer::Failed` -> degraded -> fail-open for a possibly newly flagged package. Nothing is cached on failure, so the attacker repeats. The victim loses protection only when it lands in the attacker's window; several credentials widen it. Cost to attacker is 600 keys/min per credential.
Smallest correction: when a follower receives Failed (or its wait ends because the leader's deadline passed), retry once as its own leader with its own deadline, charged to the follower; or give leader batches a per-leader size cap smaller than the whole request (e.g. 256, the client's batch) so a big batch cannot hold keys. Closure check: attacker batch of 1000 keys that times out does not degrade a concurrent single-key request from another credential; legitimate coalescing of a healthy leader still makes one upstream call.

### SEC-3 Medium (conditional on the documented trusted-proxy deployment), confirmed: pre-auth throttle keyed on the TCP peer, applied before authentication
Location: crates/probation-server/src/osv.rs:355-358, 285-291, 276-283; contrast sync.rs `source_address` (XFF-aware).
Behind a load balancer in `trusted_proxies` the peer is the proxy for every client. An unauthenticated attacker sending 10 bad bearer tokens per minute through the proxy makes `preauth_blocked` return 429 for every endpoint behind it, including valid credentials, because the check precedes auth and valid requests are not exempt. Without a proxy, NAT'd tenants share the same fate, and a firewall whose `allowed_source_cidrs` is misconfigured throttles itself (SourceRefused counts as a failure). Impact is OSV-only (endpoints fail open, stale matches kept) but it removes new-match protection fleet-wide. The same table also lets an attacker with many source addresses (IPv6 /64) bypass it, and above 10,000 entries every failed request runs an O(n) `retain` under the mutex (osv.rs:287-289).
Smallest correction: key the throttle on the same derived source as `/sync` (`source_address`), skip the block for requests that authenticate (check order: auth first through the bounded gate, throttle only to limit repeated failures), and cap the table with LRU instead of full retain. Closure check: 11 bad tokens from one client address behind a trusted proxy do not 429 a valid token from another address; 11 bad tokens from one address still 429 that address.

### SEC-4 Low, confirmed: authenticated cache-hit traffic is unmetered and has no concurrency bound
Location: osv.rs:376-392, 451. `admit` only needs tokens >= 1; charges happen only for cache misses; a body up to 1 MiB is fully parsed into a `Node` tree on every request. A holder of one credential can keep the budget untouched (repeat cached keys) and burn CPU on the process that also serves /sync. Correction: a small per-credential request-rate bucket and a global in-flight request semaphore for this route.

### SEC-5 Low, hardening: upstream rate exhaustion is global, not per tenant
Location: osv.rs:327-334, 526-529. One shared egress to api.osv.dev; many credentials (each 600 keys/min, burst 1000) can together trigger an upstream 429, which opens the breaker for up to 60 s for every tenant (all degraded). Consider a global key budget (below the upstream limit) with per-credential fair share, and alert on breaker openings.

### SEC-6 Low (design risk), LS-F12: private-by-default is not the default
Location: src/osv/mod.rs `effective_scope`; src/lib.rs:256-266 (`App::osv_scope`).
A registry on a non-public host with no explicit `osv_scope` is Public, so its private package names (the dependency-confusion inventory) go to the central server and then to api.osv.dev. Managed mode (no snapshot registries) and shared-service before the first snapshot also answer Public. Skip works where the scope is Private: `evaluate_scoped` returns the blind decision before any cache or queue use (mod.rs ~651), and every production caller (npm/mod.rs:477-492, pypi/mod.rs:361-378, artifacts/mod.rs:239) passes the registry scope. The unscoped `osv::evaluate` in src/artifacts/download.rs:394 is reached only in standalone mode (managed and service branches are `Decision::Allow` first), where there is no scope. No bypass found; the default is a privacy decision for the user. Option: default non-public hosts to Private when the field is absent, with an explicit "public" opt-in.

### SEC-7 Info/Low: `osv_stale_match_seconds` and settings push
Location: crates/probation-policy/src/lib.rs:24-33 (`LOCAL_ONLY_SETTINGS` does not list it); src/config.rs:728-737 (bounds 3600..604800).
A push can shorten the stale window to 1 h, but `osv_mode` (can switch OSV off) and `osv_cache_ttl_seconds` are already pushable, so the key adds no new lever beyond them. Recommendation: add it to LOCAL_ONLY_SETTINGS only if you also decide `osv_mode` stays pushable on purpose; otherwise leave it. Not exploitable by a non-admin.

### SEC-8 Info: `spawn_central` accepts any `Client`
Location: src/osv/mod.rs:476-492; src/osv/batcher.rs `send_central`. The origin comparison at `send_central` compares the URL with the origin it was built from, so it is always true; the real defense against credential leak is `central_http_client` (redirects off, https only) which lib.rs:341-352 uses. A future caller passing a redirect-following client would leak the bearer on a cross-origin redirect (reqwest keeps custom Authorization across redirects only in some versions; do not rely on it). Make `spawn_central` build its own client, or take `allow_http` instead of a client. The authorization_read_once additions (import line and `header(AUTHORIZATION, value)` in `send_central`) are otherwise safe: the credential is `Arc<str>` of the endpoint's own token/key, the header is `set_sensitive`, no `Debug` on `Central`/`CentralTarget`, the transport error text carries the URL only.

### SEC-9 Info: pagination not followed
Location: osv.rs:588-621. `next_page_token` from api.osv.dev (more than the page of vulns for one query) is ignored, so a `MAL-*` beyond the first page reads as no-match. Unknown whether api.osv.dev pages querybatch results for realistic packages; check once against a package with a very large advisory list.
