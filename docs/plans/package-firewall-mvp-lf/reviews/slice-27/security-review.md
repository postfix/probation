# Slice 27 security review (read-only, static; no E2E, compose or bench run)

Subject: uncommitted slice 27 on slice5-native-ci at 182f7f3. Verdict: no Critical/High. 1 Medium, 3 Low, rest verified sound.

## Findings

### M1 (Medium, privacy/integrity of the claim) Default scope is fail-open for private registries; the "before enabling" statement covers only the Public option
- crates/probation-server/src/portal/registries.rs:18 (template, "Default (queried)" option); src/osv/mod.rs:425-445 (`effective_scope`: any non-fixed host with no explicit value is `Public`).
- Exploit/impact: an org admin adds an internal registry (https://npm.corp.internal/) and never opens the OSV form. Every internal package name is sent to the shared policy server and api.osv.dev. The option text "Default (queried)" does not say that names leave the organisation; only the `Public: names reach the shared server` option and the per-row line `OSV queried: names reach the shared server` do. The per-row line is accurate (it derives from `effective_scope`, osv_view.rs:46-55) but is shown only after the registry exists. The statement is therefore accurate but not shown before the leak starts for the default case.
- Fix (not applied): relabel the default option "Default (queried: names reach the shared server)", and show the same text next to the Add-registry form; consider default Private for non-fixed hosts (behaviour change, user ruling needed).

### L1 (Low) No audit record of an osv_scope change
- registries.rs:284-312 `set_osv_scope`, service_policy.rs:208-227.
- A compromised or malicious org admin switches Private to Public and nothing is logged beyond the HTTP request; names then flow to OSV. Sibling registry setters (trust, archive-origin, credential) are equally unaudited, so this is consistent with slices 18-26, but this one changes a data-egress property. Recommend an audit row (actor, registry, old, new).

### L2 (Low, hygiene) tempdir leaked per `service()` call
- tests/common/transport_load.rs:55,74 (`std::mem::forget(dir)`). Each call leaves a directory in /tmp (tmpfs/RAM on this host) that is never removed; the rated-load test and bench call it a handful of times, so small. Use a process-lifetime holder instead.

### L3 (Low, release-gate integrity) docs say four things judge a release; the workflow enforces three
- .github/workflows/release.yml:27-30 (bench + test), e2e job runs only `--suite release` (line ~50); `release-native` is gated indirectly via `native-service` (needs chain build -> release/publish/images), but `release-cluster` (docs/operations.md:2181, item 4) is in no `needs` chain of release.yml. A tag can publish with the cluster lane never run or failing. The slice evidence says cluster lanes are "authored, not executed", so this is disclosed, but docs/operations.md:2176 "each a command that fails by itself" reads as enforced. Either add cluster.yml as a `needs` job or word item 4 as a manual runbook step.
- Also note `cargo bench ... --assert` sits in the `test` job after `cargo test`; a flaky timing bound (figures were measured at load average 15-30) can fail a tag release (availability only, not a security issue). The bound is checked on shared runners; consider generous margins.

## Verified sound (no finding)

- Authorization and cross-tenant: `set_osv_scope` runs `signed_in_post` (session + CSRF via `posted`), then `org_place` (tenancy `authorized_place` for the path org), then `admin_on` (OrgAdmin/GlobalAdmin, second factor required), and the UPDATE is `WHERE id=$2 AND org_id=$3 AND removed_at IS NULL` (service_policy.rs:218), so a tenant admin cannot set or see another org's registry; a foreign id yields not_found. The catalog query is `WHERE org_id = $1 AND removed_at IS NULL` after the same place check. Negative i32 org is rejected by `u32::try_from`.
- CSRF: the new form carries the `csrf` hidden field and the POST handler validates it; CSRF-less POST path not present.
- Field validation: `osv_scope` is matched against "public" | "private" | "" else `refused`; the DB column only receives those literals (bound parameter, no SQL concatenation).
- Stored XSS: template is `ext = "html"` Askama, auto-escaped. Registry name, ecosystem tag, target URL and `row.10` are escaped on output; `row.10` and the family labels are `&'static str` / `format!` of `&'static str` mapping spellings (no user data). `data-osv-registry="{{ row.0 }}"` is an i64; `data-osv-family="{{ family.0 }}"` is a static tag. The "three-line scope text" is three fixed constants (osv_view.rs:11-15).
- OSV mapping and OCI: `osv_ecosystem(Oci)` returns None by an exhaustive match on the server-side `Ecosystem` enum (batcher.rs:34-46), and `registry_line` short-circuits None to NOT_APPLICABLE before consulting `effective_scope`. The ecosystem comes from the registry row (DB check constraint tag), not from client input; a client cannot force OSV lookups for OCI names. Unknown tags in the catalog map to NOT_APPLICABLE (fail closed in the view). `effective_scope` public-host match uses the parsed, lowercased host with exact set membership (no suffix or substring match, so `registry.npmjs.org.evil.test` is not treated as public).
- cross_plan_acceptance.rs: every path is `CARGO_MANIFEST_DIR` joined with a fixed relative literal; no env-derived paths, no `Command`/process spawn, read-only (`read_to_string`, `read_dir`).
- transport_rated_load.rs / transport_hot_paths.rs: in-process (`TestServer`, `tower` requests through the router), no TcpListener bind in these files; wiremock `MockServer` binds loopback only; upstreams are `*.invalid` fake registry. Only `--assert` is read from argv; `/proc/self/status` read-only. No privileges needed. Only residue is L2.
- release.yml: top-level `permissions: contents: read`; `id-token: write` only on `release` and `attest`; `contents: write` on `release`/`publish-release`; `packages: write` on `images`; `security-events` only on codeql. Action refs are SHA-pinned with version comments. The new bench step takes no secrets (test job has none, `persist-credentials: false`) and no external input. `${{ github.ref_name }}` is interpolated into `run:` in the two Package steps (pre-existing); tag filter `v*.*.*` still permits shell metacharacters in a tag name for anyone who can push tags (maintainers only); recommend passing via `env:` (pre-existing, Low, not slice 27).
- run.mjs: `--suite` is validated against the `SUITES` allowlist; `--only` ids are filtered against known scenario ids (run.mjs:56-62); `startsWith("release")` only widens to the three release suites; no shell interpolation of these values.
- native-service.yml Maven seed step: mirror to `https://repo.maven.apache.org/maven2/` (https, Maven Central; Maven verifies checksums from the repo but not signatures: same trust as the previous step), no credentials, settings.xml written under `$RUNNER_TEMP` with a fixed id `probation`; `mirrorOf *` is confined to the seed project's `-s` file, not the runner's global settings. Plugin version pinned (3.8.1). No untrusted input interpolated.
- docs figures: the OSV paragraph (operations.md:2183) matches `registry_line`; the rated-load table is labelled as development-host, in-process, no TLS, and claims no per-family warm metadata figure (no overstated security/performance claim found).
