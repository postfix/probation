## Spec changes needed (04/03/00-status are not edited)

1. 03 "Configuration, data and platform contract" and the 04 row: the supervision details are now decided and tested: launchd `KeepAlive` is the dictionary `{SuccessfulExit: false}` (not the research's boolean `KeepAlive true`, which also restarts an exit 0 stop), `ThrottleInterval 5`, `ExitTimeOut 45`, `Umask 63`; Linux keeps `RestartSec=2` (03 gives 5 s only for macOS and Windows).
2. The settings restart on Windows: the service host reports no `Stopped` for exit 75 or a failure, and the installer sets `failureflag 0` so only that path restarts; 03 should say so (the research already does).
3. `windows-service` is now a pinned Windows-only dependency (03 already plans it); Cargo.lock grows by `windows-service 0.8.1` and `widestring 1.2.1`.
4. "Second owner": it is the data-directory flock plus the installer's refusal to take over a service of that name; there is no separate owner lock. Say so in 03.
5. Public URL: the product requires `public_url` to be https even for a plain-HTTP loopback listener (a metadata rewrite would otherwise point clients at an http URL it cannot serve), so a native install either names an existing certificate (`--tls-cert/--tls-key`) or sits behind a TLS terminator; the installer never generates TLS material. install-local.sh still does.
6. `install-local.sh` keeps its own inline unit and the journald-namespace fallback (it gained `TimeoutStopSec=45` and `UMask=0077`); the "consolidate generated units" intent of design-deployment-contract.md is delivered for the new installer only (install-service.sh also supports `--log-namespace` with the same fallback). Converting install-local.sh to call install-service.sh is left: it needs a migration path for units an older install-local.sh wrote (no manifest), which can only be tested on a machine with a real system systemd.
7. 04 row 25 gate: `check_workflow.py` now also pins that release, publish and images need `native-service`; the row's "Linux/macOS/Windows runtime jobs" are the jobs named in Lanes.
8. The release macOS and Windows binaries link OpenSSL's libcrypto dynamically (`#[link(name = "crypto")]`, the OCSP code): release.yml now runs `openssl-setup.mjs` and ships `libcrypto-3*.dll` in the Windows zip, but a macOS tarball still depends on a Homebrew dylib path. Whether that runs on a machine without Homebrew OpenSSL is unverified and needs a decision on vendoring or static linking.

## Remaining limits (stubs, hardcoded values; the packet has no "Remaining stubs and limits" entry, so each is listed here and none is claimed fixed)

- Windows operational log: under the SCM stdout goes nowhere, so the JSON operational events (listening, shutting down, startup errors) are lost; only the decision log file (the installer sets `log_file_path`) and the SCM's own status/exit codes remain. A file sink for the operational log in service mode is not built.
- Windows service-key ACL: `service_policy.service_key_file` is checked as a private file by mode bits on Unix only; on Windows the installer's ACL on the config directory is the control (documented in config.rs and operations.md), not a code check.
- Windows `PreshutdownTimeout` is set as a registry value; Microsoft documents it through `ChangeServiceConfig2(SERVICE_CONFIG_PRESHUTDOWN_INFO)`; unverified on a runner.
- Maven and Conan native tests drive pinned podman images; macOS and Windows runners have no native-host mode for those two families (a host-tool mode in maven_native.rs and conan_native.rs and pinned Java/Maven/Conan provisioning is not built).
- The macOS stdout log and `newsyslog.d` rotation, the `dscl` account creation, `launchctl` verbs and the plist permission question are unexecuted.
- `--root` staging runs no service manager, account or ownership command, so ownership of staged files is never asserted (modes are).
- install-service.sh on a system install runs `check-config` as the service account only when it runs as root; the staged and user-scope paths run it as the invoking user.
- A system lane run as root through `sudo -E env PATH=...` runs the native npm and pip as root on the throwaway runner.
- The docker-engine.sh digest was recorded from this session's download of the vendor archive; the vendor publishes no checksum file for static builds.
- No Kubernetes, no node, no Docker Desktop (rows 26/27 and the design's desktop runners).
