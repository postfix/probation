## Measured against the real registry and the real clients (Docker Hub, 2026-11-20; podman 5.4.2; containerd 2.2.0)

- Largest real inputs: the index of `library/python` 10,954 bytes (18 manifests), `library/alpine` 9,218 (16), `library/nginx` 10,229 (16), `library/golang` 9,695 (16); an image manifest 2,318 bytes (7 layers); the tag list of `library/python` 85,096 bytes (4,127 tags, one page, no `Link`); nothing is compressed on the wire. ## Behaviour notes (decisions inside the contracts)
- Identity. Policy sees the repository (`library/alpine`) as the name and the manifest digest (`sha256:...`) as the version (the exact text; lower case is the grammar, so a name with an upper-case letter is a 404 before anything is asked); a block may also name a tag, and then applies to every request that names it (checked before any registry call, for the manifest, the tag list and the blob routes). A reference row's `filename` is `manifests/{digest}` or `blobs/{digest}`; every upstream URL is rebuilt from the parsed identity. A path that is not exactly one canonical spelling (an upper-case, empty or dot segment, a digest of an algorithm the firewall cannot verify, a query key the route does not take) is a 404 before any admission or upstream call.
- Dates. A registry's v2 API carries no publication time; the config's `created` and an annotation are the depositor's word and release NOTHING (the test config says 2001 and its image is held). The age of a manifest digest is the committed first-seen time of its row (the clock starts when the firewall first sees the digest, in the store, surviving restarts), so an image already on the registry waits one cooldown from first sight (the safe direction). A child (an index's manifest, a config, a layer) takes the date of the manifest that named it once that manifest is ALLOWED (a date only ever gets later); a blob nobody named is a direct request with its own first-seen time. A tag is only a name: every request for one asks the registry and judges the digest it names now (a moved tag is a new digest with its own age; the old digest is still served by name). This is the 03 family-table rule ("Missing trustworthy publication date uses digest first-seen; image config build time does not establish publication time"); the user's brief named config `created` / registry push time as dating inputs: neither is a trustworthy time, and no registry API offers a push time (Hub's is a private web API), so first-seen is the date. Residual U1, same class as Go's first list, NuGet's `published`, Maven's `Last-Modified` and Conan's revision time: none of these is back-datable here (nothing a depositor writes is read as a time), only longer than necessary.
- Digest identity. The manifest's bytes are hashed in the algorithm of the digest asked for (a tag: sha256) and must equal it, and equal the registry's `Docker-Content-Digest` when it sends one (502 otherwise); the served bytes, `Content-Type` and `Docker-Content-Digest` are the registry's exact bytes; a layer is hashed in full against its digest by the verified artifact pipeline before the first byte is delivered and a mismatch pins nothing (`a_layer_whose_bytes_are_not_its_digest_is_refused`); Range, HEAD and resumed pulls are served from verified bytes. `sha256` and `sha512` are verified; another algorithm is a 404.
- Rows and bounds. A manifest's own row is committed on first sight (it carries the clock) and, once ALLOWED, one batch commits a row for each digest it names (config, layers, child manifests, deduplicated, at most 20,000), all inside the repository's row gate, which is held from the bound check to the commit: a repository holds at most five times `max_references_per_project` rows; past it the manifest is a 503 and its children commit nothing (`the_row_bound_is_hard_and_atomic`, `simultaneous_first_requests_never_overshoot_the_row_bound`).
- Fetches. Every registry exchange holds a place of the registry (8), of the caller's credential (2 of those) and of the process (half of `max_upstream_requests`, at most 32): `one_credential_cannot_hold_all_of_a_registrys_fetch_places` (8 callers with one token peak at 2, 16 callers with different tokens peak at 8). Every document request has a 120 s deadline.
- Tables. Anonymous tokens 256, realms 64, per-registry places and per-credential places 1,024 each, row gates 1,024, a manifest memo of 256 entries for 60 s (only for a digest, only for a read the allow-list of LS-F4 classed cache-eligible), existence checks 4,096 for 30 s (same rule), registered manifests 4,096 for an hour; none grows with the number of repositories (`the_process_tables_stay_bounded`).
- The registry's own token flow, unchanged for the client. In a shared service `GET /v2/` mirrors the registry's own state (found by the real skopeo: a ping answered "open" because an anonymous token was available made the client never present its credential, and its push met a 401 it did not act on): open (200), a client that already carries a credential (200), or the challenge even for a public registry that wants tokens (the client's own anonymous token request is relayed); a standalone firewall answers 200 and takes its own anonymous token; a request that skips the ping is served with the firewall's own anonymous token. The challenge is `Bearer realm=<this firewall>/v2/token,service=probation` or, for a registry that takes Basic directly, Basic. `GET /v2/token` is this firewall's token endpoint: a certificate-managed firewall answers it with the API key as the token (the Basic password or Bearer, as Conan's login), a shared service asks the registry's own realm with the caller's Basic credential and rebuilds `{"token","access_token","expires_in"}`; scopes are `repository:{name}:{pull|push|delete|*}` and `registry:catalog:*` only (anything else, any other key, is a 404). A realm is the registry's own origin or the one token host a registry is known by (`registry-1.docker.io` -> `auth.docker.io`, `ghcr.io`, `quay.io`, `gcr.io`, `public.ecr.aws`); any other realm is never asked and no credential goes to it (`a_token_realm_on_another_host_is_never_asked`, `a_basic_credential_is_exchanged_for_a_token_at_the_registrys_realm_only`). The caller's Bearer token goes to the registry's origin only; the firewall's own key is never an upstream credential on a write (a firewall key presented as the registry credential is a 403 and nothing is forwarded).
- Authentication is by the installed client's own token, not certificates: the certificate script says so on stderr and writes no OCI configuration (unit test `oci_setup_points_at_the_key_route`), the Keys page shows `docker login` and `docker pull`.
- Blob redirects. A blob `GET` is fetched by the artifact pipeline, which follows the registry's redirect only to the storage origin (`oci_artifacts_url` / Hub's two / the selected registry's declared archive origin) and drops the credential at the first hop; a client is never redirected (no storage URL reaches it). Witnessed on real sockets (`a_blobs_redirect_reaches_the_storage_origin_without_the_callers_credential`, `a_redirect_to_any_other_origin_or_without_permission_is_refused_and_nothing_is_asked`) and by podman (`the storage host never saw a credential`).
- HEAD. An anonymous HEAD is judged exactly like a GET (a blob HEAD runs the cold verification, as every family's does). A HEAD with the caller's own credential is an existence check (a push asks before it uploads a layer or tags a manifest): for a manifest the cooldown does not hold it (a block still does, and the manifest is still fetched and hashed); for a blob it is the registry's own answer (existence, size, digest), no bytes. Without this a `docker push` of an image whose base layers exist on the registry would be refused at its first existence check (the analogue of slice 23's uploader exemption, without per-credential memory: the exemption is the verb and the credential).
- Writes (class W, shared service only). `POST` (start, with `digest=` monolithic or `mount=`/`from=`), `PATCH`, `PUT`, `GET` and `DELETE` of an upload session, manifest `PUT` and `DELETE`, blob `DELETE`: with the caller's own `Authorization` (never the service key) to the registry's own origin (its `target_url`, path included). A write without a credential is answered `401` with the challenge (scope `repository:{name}:pull,push`) before anything is read or asked, a firewall key as the credential is a 403, a declared body over the cap is 413 before the registry is asked, the registry's answer is relayed only with a status a write endpoint gives, with `Location` rewritten into the firewall's namespace (an absolute URL of the registry's own origin and prefix, or a path under it; any other, a 502), `Range`, `Docker-Upload-UUID`, `Docker-Content-Digest` filtered by shape, the body as JSON or `text/plain` with `nosniff`. A body is spooled by the one shared spool (src/http/spool.rs; owner by `spool::owner_of`: the account in certificate mode, the client address /64 and credential in service mode; half-share, budget, rate floor, first-chunk wait) up to twice `max_artifact_bytes`: a multi-GiB layer streams to disk and is forwarded with the length it turned out to have (`a_chunked_blob_upload_is_spooled_and_forwarded_with_its_real_length`); nothing regressed for the other forwarders (their binaries pass). A layer larger than twice the artifact cap is a 413 (and one larger than the cap cannot be pulled either: the same bound). A standalone or certificate-managed firewall has no write route (405).
- Lists. Tag lists, the catalog and a referrers index are typed-decoded (no `Value` tree), bounded (500,000 entries, the document cap) and REBUILT: tags and repositories that are not names, and any a block names, are dropped; a referrers descriptor keeps `mediaType`, `digest`, `size`, `artifactType` and bounded annotations; every `Link` is rewritten to the same list in the client's namespace carrying only its paging keys, or dropped (a link to another host, another list or another relation is no link), so pagination cannot lead a client around the firewall. A tag's age is not judged in a list (that would cost one manifest fetch per tag): fetching a held tag is the 403.
- C1028. A read that carries a credential, or anything the allow-list does not know (a cookie, an unknown header, `?token=`), is request-scoped: it reads and fills nothing shared (no manifest memo, no existence memo, no stored blob) and is served from nothing shared; the family adds `docker-distribution-api-version` and the query keys `ns`, `n`, `last`, `artifactType` to LS-F4; no route takes a credential in its path or query (`credential_bearing_read_never_enters_shared_caches_oci_end_to_end`, the path forms are 404 with no registry call).
- Publication gate (FIX-16-A). In a shared service the one shared layer (`service_registry::respond`) refuses a finished response when a publication landed meanwhile and `readmit` admits the request again under the new snapshot (`a_publication_between_authorisation_and_release_is_admitted_again`: one publication served, a change that keeps landing a 503 after three admissions, for a manifest, a tag list, a blob and the ping). On the certificate-managed key route the document is decided under the policy the key had at admission; after the registry calls the key is re-read without charging its rate a second time (`Managed::reauthenticate`) and a changed policy is admitted again (`an_oci_manifest_is_not_served_under_a_layer_that_a_publication_replaced_mid_request`, `an_oci_read_costs_one_rate_token`).
- OSV. The mapping is `None` (03 "Central OSV lookup"); scope never applies and no name of an image reaches an OSV server (`osv_not_applicable_to_oci`).
- Reporting. `Upstreams.oci` is additive in both directions (`oci_reachability_is_additive_in_both_directions`); a tracker for the OCI call reports only after the first call.

## Not done, limits and decisions
- Only `sha256` and `sha512` digests are verified; another algorithm in a path is a 404 and in a manifest a 502 (the firewall could not vouch for it).
- The catalog is served as a registry serves it (Docker Hub has none: its 404/401 is the answer); a catalog is not judged per repository beyond a block's names.
- E2E environment (not product): three scenarios of earlier slices (the cargo, maven and NuGet service publishers) and mine failed with 3 s to 10 s stalls through `fw-standalone.e2e.test` after I had stopped and recreated the stack many times: aardvark-dns kept a stale second address (`11.220.0.6`) for `firewall-standalone` in `/run/user/1000/containers/networks/aardvark-dns/probation-e2e_e2e%int` (measured from the gateway: `getent ahosts firewall-standalone` listed it; a `curl` by name took 3.06 s to connect, by the live address 0.000 s). Removing that stack's aardvark files (mine) and running again passed every scenario, with no retry in any of them.
- A tag list shows the tags a block does not name; a held tag is a 403 when fetched (its age is its digest's, which a list does not know).
- A blob's membership is the persisted row (made when an allowed manifest named it, or when it was first asked for) plus a live existence check of the registry (30 s for an anonymous caller, none for a credentialed one); a blob a registry removed is a 404 within 30 s, a manifest removed is a 404 at once.
- A layer larger than twice `max_artifact_bytes` (10 GiB by default) is a 413 on push and larger than `max_artifact_bytes` (5 GiB) cannot be pulled; both are the configured bounds, not an OCI limit.
- Coverage gap (mutation probe P18 survived): the 4,096-entry bound of the registered-manifest memo is in the code and not witnessed by a test.
- Conditional requests (`If-None-Match`) are answered with the full document; `Range` on a manifest is ignored.
- Schema 1 manifests (`fsLayers`) are read and vouched for; their signature is not checked (a client verifies its own).
- A registry that answers a blob `HEAD` with a redirect is treated as having it (the redirect is never followed on a HEAD).
- Docker Hub rate limits an anonymous caller by the firewall's address (documented); a credentialed client is counted for its account.
