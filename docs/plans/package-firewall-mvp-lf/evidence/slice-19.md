## Behaviour notes (decisions inside the contracts)
- Identity and case. The policy key, blocklist and OSV key are the DECODED module path (Go module paths are case-sensitive: `github.com/Azure/x` and `github.com/azure/x` are two modules, and OSV agrees: `golang.org/x/Text` finds nothing where `golang.org/x/text` does, api.osv.dev 2026-11-19) and the version without its `v` with `+incompatible` kept (OSV answers `0.3.0` and `v0.3.0` alike for golang.org/x/text, and `3.2.0+incompatible` and `3.2.0` alike for dgrijalva/jwt-go: the unprefixed form is sent as 03 says, LS-F6 canary recorded). The URL and the file name keep the proxy's `!`-escaped spelling and are REBUILT from the decoded identity (never taken from the request): decoding is strict (an upper-case letter on the wire, `!` before a non-letter, a trailing `!`, `!!` or non-ASCII is no spelling at all), so there is exactly one escaped spelling of every module and version, `escape(unescape(p)) == p` for every accepted `p`, and a second spelling is a 404 before any upstream call (tests `escaping_round_trips_...`, `request_paths_parse_to_one_canonical_identity`, `invalid_spellings_are_404_before_any_upstream_call`, `mixed_case_modules_and_versions_keep_one_identity_end_to_end`, real go in `native_go_downloads_a_mixed_case_module_and_version`, E2E-go). A module path needs a dot in its first element (what `go` itself requires), which also keeps `sumdb/...` from ever being a module.
- Dates. The proxy protocol has no per-module document with times; a version's real publication time is the `Time` of its own `.info` (the fixed public proxy writes it for every version, checked 2026-11-19 on pkg/errors and kubernetes). It is read, never invented, kept per module in a bounded in-memory table, and committed on the three reference rows. `Time` absent or the zero time (Athens writes it for a module it never dated): the committed first-seen time, so the version is held for a whole cooldown and never dated from a cache age or a build time. `Time` present but unparseable: the version is refused (502; withheld from a list), never dated. A re-dated version can only get later (the later of the two dates is kept). Pseudo-versions are never in a list; each is judged by its own `.info`. `.mod` and `.zip` are judged with the `.info` date of their version, so a held version's three files are all refused (403) and its `.mod` and `.zip` are never fetched.
- List fan-out (bounded before any upstream call). A list needs one `.info` per version of unknown age. One request makes at most 64 `.info` calls (8 at a time, newest versions first, none for a version a block already refuses outright); a version still undated after that is WITHHELD (fail closed) and is dated by a later request, so a long list of a module this firewall has not seen completes over a few requests (`list_fan_out_is_bounded_...`). A list with more than a third of `max_references_per_project` versions (6,666 by default), over `max(max_metadata_bytes, 16 MiB)`, or not UTF-8 is refused (502). Largest real lists, measured 2026-11-19 (proxy.golang.org sends them uncompressed: gzip changes nothing): github.com/aws/aws-sdk-go 1,865 versions / 16,281 bytes, k8s.io/kubernetes 1,253 / 14,408, hashicorp/terraform 482 / 5,450, moby/moby 348 / 5,761. The 16 MiB floor is more than 1,000x the largest.
- `@latest`. The proxy's own answer when it passes policy; else the highest allowed release (or, with no release, the highest allowed prerelease) of the filtered list; else 404. The answer is then served as that version's `.info` through the same gate. A proxy with no `@latest` endpoint still offers its allowed list.
- Local gate first. A blocked module or version (name and version are all a block needs) is refused 403 before any upstream call, in the managed key route with a decision record (`locally_blocked`; `go_key_route_authenticates_every_read_and_refuses_a_blocked_module_locally`).
- Caches and C1028. The only metadata memory is the in-memory version table per (registry, origin, module); persisted state is reference identity, first-seen and pins only (`commit_request_references_in`, no response body is stored in any mode). A request that carries the caller's credential (any non-allow-listed header) reads and fills NOTHING shared: it gets a throwaway table and confirms the version itself (three `.info` calls: reference, membership before the transfer, membership after it, SPEC §9), and its zip is held in a request-owned file (`credential_bearing_read_never_enters_shared_caches_go_end_to_end`, `credential_bearing_reads_share_no_version_memory`). Existence is confirmed again after `metadata_ttl_seconds` (5 s through the shared service): a version the proxy no longer has is 404 even when its zip is stored.
- Single flight. One list fan-out per module at a time, and a request that finds one running does not wait for it (it answers at once with what is dated, so a burst of lists of a slow module never pins request permits);  different versions' `.info` fetches are not serialised (a hung fetch never blocks a module). Duplicate fetches of one version are bounded by the request permits.
- Zips. Delivered exactly as the proxy sent them through the shared artifact pipeline: never opened, repacked or inflated (so no inflate cap applies; the cap is `max_artifact_bytes`, 5 GiB, far above Go's own 500 MiB limit), the first verified download pins its digest, a later different body is refused, and `go` verifies the h1 hash against go.sum and the checksum database itself (live witness below). Largest zips sampled 2026-11-19: Azure/azure-sdk-for-go v68.0.0+incompatible 69,068,229 bytes, aws-sdk-go v1.55.5 36,031,361, cilium v1.15.0 28,878,943, k8s.io/kubernetes v1.30.0 18,609,332; the largest `.mod` 12,820 bytes (kubernetes); `.info` about 200 bytes (the cap is 256 KiB).
- Archive redirect (found live, not in the plan). proxy.golang.org answers a zip of 10 MB or more with a `302` to `https://storage.googleapis.com/proxy-golang-org-prod/<hash>-<module>-<version>.zip?Expires=...&Signature=...` (measured: aws-sdk-go v1.44.0 25 MB, k8s v1.30.0 18.6 MB, azure v68 69 MB redirect; x/text 9.2 MB and every smaller zip are direct). The transport followed only same-origin hops, so every such module would have been a 502 (red below). The proxy's bucket is now a fixed second origin (`go_artifacts_url`, default the bucket with its path prefix), admitted as the target of an ARTIFACT redirect from the proxy only: not for a list or an info, not under another prefix of the host, not from any other origin kind, never carrying the registry credential. A selected (private) registry's archive origin is its own: a redirect away from it is refused unless the registry declares an archive origin (below), for credentialed and uncredentialed reads alike (a credentialed hop may only stay on the origin it was on or land on the declared archive origin; before the fix round it could land on any origin of the set, the public proxy and the checksum database included: security review F2).
- Checksum database (03: "a separately admitted auxiliary source, not an unprotected artifact route"). `GET /go/sumdb/{db}/supported|latest|lookup/{module}@{version}|tile/H/L/K[.p/W]` is forwarded to `go_sumdb_url` only; `{db}` must be that host; the module and version of a lookup must pass the same identity rules; tile paths are validated to the sumdb tile grammar; nothing is cached, no credential of the caller is ever sent (probe P10), only the public registry has it (a registry with its own `target_url` has no checksum record: 404 without an upstream call), and the answer is capped at 4 MiB. `go` therefore keeps its checksum verification through the firewall with `GOSUMDB` unchanged.
- LS-F4 allow-list. Real `go` 1.26.0 sends only the common headers on a plain read (Accept-Encoding, User-Agent, Host: `go_native_client_sends_only_allow_listed_headers`, measured with `get`, `list -m -versions` and `mod download`), so the family list is empty. Credentials travel as `Authorization` (Basic from `.netrc` or the GOPROXY userinfo; `go` refuses credentials over plain http, so the key route needs https, which the E2E gateway has), request-scoped. No route takes a token in its path or query; the path-embedded and userinfo forms of the family are in the family test, and a path that is not one of the routes is a 404 that asks upstream nothing.
- One protected proxy. The keys page shows a single `GOPROXY` URL (no `,direct`, no `|`) and docs/operations.md says why: with a comma `go` falls back on 404 and 410, with `|` on any error. The firewall cannot make the client's list safe; `native_go_with_one_protected_proxy_does_not_fall_back_on_a_refusal` records the client behaviour with a `|off` list.

## Writes
GOPROXY has no write protocol: a module is published by pushing a tag to its repository and the proxy discovers it. There is nothing to forward through the shared service, so every non-read request on a Go route is refused (405/404, nothing reaches upstream: `go_is_read_only_through_the_shared_service`, E2E-go's write verbs, the route table's two read-only rows). Row 18's write forwarding (publish, yank, owners) has no Go counterpart.

## LS-F7: the family's inputs and caps
- No Go input is inflated. Lists, infos and mods arrive as plain text (the proxy sends no `Content-Encoding`; the transport's own 100:1 ratio rule applies to a mirror that does), zips stream to the content store and are hashed. Caps: list `max(max_metadata_bytes, 16 MiB)`, info 256 KiB, zip `max_artifact_bytes`. No valid input is refused before those caps (largest measured above).

## Decisions for the user (defaults chosen; nothing here is a request to build or drop a feature)
1. List fan-out cap 64 per request with the rest withheld until dated (a long list of an unseen module completes over a few requests). Alternative: raise the cap (the 03 text names no number); default kept.
2. `.info` and `.mod` are delivered through the artifact pipeline, so each is pinned by the digest of its first verified download (SPEC §9) like a zip. A proxy that answers the same version's `.info` with different bytes later (a changed `Origin` field, say) is refused 502 as an integrity failure. Default: keep (immutability is the Go proxy contract). Alternative: pin zips and mods only.
3. A module path needs a dot in its first element (what `go` requires itself; keeps `sumdb/` out of module space). A proxy serving dotless internal paths would be refused. Default: keep.
4. The checksum route exists on the public registry only. A registry with its own `target_url` has none (404): its modules are expected under `GOPRIVATE`/`GONOSUMDB`.

## Fix round (reviews/slice-19/code-review.md and security-review.md; every finding fixed, nothing dropped)

The pin stays (user default). The old test is renamed to what it proves (`a_zip_changed_upstream_is_still_served_from_the_verified_store`).
- **G19-2 revision queries (built).** `GET {module}/@v/{rev}.info` for a token that is not a canonical version (`go get mod@main`, `@v1`, `@<commit>`): the token is validated before any upstream call (`[A-Za-z0-9._+-]`, 1 to 128 bytes, lower case on the wire, no leading `.` or `-`, no `..`, not a canonical version; `.mod` and `.zip` never take a revision), counted per (registry, module) (at most 32 distinct per minute, 429 beyond, no upstream call for the refused one), resolved by upstream, and the RESOLVED version (its `Version` must be a canonical version; its `Time` is the date) goes through the ordinary gate: a blocked resolved version is refused before it is recorded, a held one is 403 and its `.mod` and `.zip` are never fetched; the answer is that version's `.info` through the artifact pipeline (which judges it again). Tests: `revision_queries_resolve_upstream_and_the_resolved_version_is_gated`, `revision_queries_are_bounded_per_module_and_validated_before_any_upstream_call`, `invalid_spellings_are_404_before_any_upstream_call` (more tokens), real go `native_go_resolves_a_branch_and_a_commit_and_a_young_branch_is_held` (`go get mod@main`, `@<commit>`, a young branch), E2E-go.
