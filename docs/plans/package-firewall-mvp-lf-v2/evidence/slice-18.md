## Behaviour notes (decisions inside the contracts)
- Dates. The real crates.io index carries `pubtime` (RFC 3339, `Z`) on every line (checked 2026-11-19 on serde, proc-macro-error; 316 lines of serde carry it). The plan names `created_at`; both are read, and when both are present the later one is used, so a disagreement can only hold a version longer. A line with neither waits on the committed first-seen time; an unparseable value counts as absent (first-seen is never earlier than the real date, so this can only hold longer); a future date is denied by the existing rule. No cache-age or build-time substitute.
- Identity. Project row, reference name, policy, blocklist and OSV key by `canonical_name` (lower case, `_` to `-`); OSV was asked live for `proc-macro-error` under `proc-macro-error`, `proc_macro_error` and `Proc-Macro-Error` and answered the same advisory each time (api.osv.dev, 2026-11-19), so the folded spelling is safe as the OSV key. The index path and the archive file name keep the registry's own spelling: the path is the lower-case name exactly (an upper-case path, or a prefix that does not belong to the name, is 404 before any upstream call), the file is `{name}-{vers}.crate` with the name exactly as the index line spells it (`Inflector`), and the download route compares crate name and version exactly. `1.0.0+build` and `1.0.0` are one version for policy and OSV (build metadata dropped, LS-F6) while the archive keeps it in its file name and URL.
- Spellings. A hostile or odd registry could answer many `-`/`_` spellings of one name; at most 4 exact spellings per (registry, crate) are committed per process (the same bound and ceiling as RubyGems R1, marked `ponytail:`), a 404 is remembered under the exact spelling asked for so `foo-bar` missing never hides `foo_bar`, and a stored row that belongs to another spelling is not served under this one.
- `config.json`. Fetched with the caller's read authorization, parsed (`dl`, `api`, `auth-required`), cached 60 s per (registry, origin) with one fetch at a time, a failure 15 s, never read or filled by a credential-bearing request (C1028). The served `config.json` names this firewall for `dl` (`{public}/cargo/crates`; Cargo appends `/{crate}/{version}/download`) and `api` (only when upstream has one) and keeps `auth-required`; a managed firewall on the key route adds `auth-required` itself and answers an unauthenticated read with `401` carrying both `WWW-Authenticate: Basic` and `Cargo login_url="..."`.
- `dl` origin rule. Every archive URL is built from the registry's own `dl` (all five cargo markers, or `/{crate}/{version}/download` appended) and admitted against the archive origin: `cargo_artifacts_url` for the fixed public source, and for a selected registry the registry's own `target_url` origin and path. A `dl` on another host, port or path, with userinfo, a query, or a non-http(s) scheme refuses the whole listing (502) and is never fetched. Consequence: a mirror whose archives live outside the path of its index URL (Artifactory's `api/cargo/{repo}/crates` beside `.../index`) is refused until its `target_url` is a common prefix; see "Decisions".
- Verification. The archive's SHA-256 must equal the `cksum` of the same index line (the shared artifact pipeline verifies it, nothing is delivered before it matches); a mismatch is 502 and the bytes never reach the client. A yanked line is kept and its archive delivered (lockfiles name yanked versions: real cargo fetches one in tests/cargo_native.rs).
- Filtering never re-encodes: kept lines are upstream's text, byte for byte. A line that is not well-formed (not JSON, a duplicate known field, a version that is not SemVer, a checksum that is not 64 hex digits, a name that is not LS-F6) is dropped, never delivered; a document with lines and none usable, with two lines for one version, or with a line of another crate is refused (502).
- The filtered index carries a strong ETag of its own body and answers `If-None-Match` with 304; policy changes change the body and with it the validator, so a stale 304 cannot happen (probe P12).
- LS-F4 allow-list. Real cargo adds `Cargo-Protocol: version=1` and, over plain http, libcurl's `Upgrade: h2c` and `HTTP2-Settings`; the plan's assumption of an empty list was wrong and the real client witness found it (red in tdd-slice-18.md). Credentials: the registry token travels as `Authorization` (bare or `Bearer`), request-scoped; no Cargo route takes a token in its path or query. The path-embedded credential forms of the family (a registry URL with userinfo, a token spliced into a path such as Cloudsmith's) are in the family test: userinfo forms are request-scoped, and a path that is not one of this firewall's routes is a 404 that asks upstream nothing.
- Shared service: Cargo is read-only (GET and HEAD, no query string): `cargo publish`, `yank`, `unyank` and `owner` are not forwarded.

## LS-F7: largest real Cargo input and the cap
- index.crates.io does not compress its index files: with `Accept-Encoding: gzip` the answer has no `Content-Encoding` (2026-11-19, one GET each). Largest sampled files, inflated bytes: aws-sdk-ec2 1,484,079 (346 lines, longest line 5,156), windows 1,403,289 (81 lines, longest line 32,692), rustix 1,144,698, aws-sdk-sagemaker 878,960, windows-sys 491,298. Our own gzip of the largest is 35,335 bytes (42:1), so a mirror that does compress is well inside the 100:1 rule the transport applies.
- The `.crate` archives are never inflated by the firewall (streamed to the content store and hashed), so no inflate cap applies to them.
- Cap: the index fetch uses `max(max_metadata_bytes, 16 MiB)`; the shipped `max_metadata_bytes` is 64 MiB, which is 43x the largest file measured, and the 16 MiB floor is the LS-F7 minimum (at least 4x 1.48 MB = 5.9 MB). No valid input is refused before the cap; `tests/cargo_registry.rs::the_largest_real_index_sized_document_is_not_refused` serves a 1.4 MB, 4,000-line document.

## What the real client taught (not in the plan)
- Cargo refuses an authenticated registry that has no credential provider ("authenticated registries require a credential-provider to be configured") and, for a source replacement, "no token found" unless the replaced source is also named by a `[registries.NAME]` entry with the same `index`. The keys page and docs/operations.md therefore show `[source.*]`, `[registries.*] index` and `credential-provider = "cargo:token"` plus the token stored as `Bearer ...` (Cargo sends the token as written). Found by the E2E run; tried against a stand-in server with the variants first (A: source and token only, B: plus the global provider, C: a named registry, D and E: both entries with the provider) and E2E-cargo is green on D.
- Cargo has no client-certificate setting (`[http]` has `cainfo`, `ssl-version`, not a certificate). A managed-certificate organisation cannot sign Cargo in with a certificate; the certificate script says so on stderr and writes no Cargo configuration (unit test). Key mode and shared-service mode work.
- Aliases. The plan's "alias handling" is a policy rule, not a routing rule: crates.io has one index file per published spelling (`/pr/oc/proc_macro_error` is 404, `/pr/oc/proc-macro-error` is 200, 2026-11-19) and real Cargo needs the dependency spelled exactly, asking the other spelling only to print "help: packages with similar names". I first expected Cargo to retry the other spelling and wrote a test for that; real cargo 1.96 refused (red in tdd-slice-18.md), so the test now pins the real behaviour: the near-miss spelling is 404 with Cargo's own hint, the exact spelling resolves, fetches and unpacks, and the firewall adds no alias crates.io does not have. Blocks and OSV treat every spelling as one crate (tests/cargo_registry.rs).
