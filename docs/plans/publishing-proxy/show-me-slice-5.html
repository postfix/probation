Slice 5: Native package-client release acceptance (publishing-proxy)

Delivered

A release can now prove, on Linux, macOS and Windows hosted runners, that the real npm and Python package clients publish, install and are refused correctly through the Probation service, with no certificate setup and no registry credentials held by the firewall. Before this slice, only a Linux Docker harness exercised the clients and the service did not build on Windows. Now each of the three native jobs builds the real probation binary, runs it with loopback Node fake registries, and runs 75 client-facing checks (npm publish, install, view, audit, deprecate, unpublish, token-packument; Python via Twine, pip and uv). Each job is judged against the real Linux policy server, reached through a filtering proxy and a pinned cloudflared quick tunnel (macOS and Windows cannot run the server). Deciding refusals that the checks assert: denied publish, deprecate, unpublish and upload return 403 with a new upstream row; a policy-hidden package serves no bytes to any caller; an unknown registry ID or an npm ID under the PyPI path is refused with zero upstream calls; the policy key reaches only the snapshot endpoint and never a registry.

Required guarantees versus observed results are separate in the table below. The release workflow keeps the native job as a required needs of release and publish (tdd-slice-5.md, C6/D1/H1; checker mutations only, structure not an execution witness).

Limits

Accepted by the user on 2026-11-09:

  • Windows ACLs on the service key file and delivery log are not verified (stack.mjs restricts the key with icacls; the product check is POSIX-only).
  • Windows directory-entry durability relies on NTFS journaling; a crash right after the refusal marker could re-admit a refused grant for one restart plus one poll interval.
  • macOS pf redirect with a warned wildcard-bind fallback; on the hosted darwin job the fallback did not fire.
  • Public cloudflared quick tunnel with a filtering proxy, plus a 1-day native-handshake artifact holding the tunnel URL and a throwaway key, readable by anyone with repo read access until retention ends; native-real-server-logs (3 days) is also readable.
  • The hard OpenSSL link in enterprise_certificate.rs is supplied by CI (follow-up: pure-Rust OCSP or vendored OpenSSL).
  • Other images pinned by tag only; apt packages in the test image unpinned; linux-managed repeats release e2e work (about 65-70 minutes); the changes poll in src/managed/sync.rs stays unpaced.

Other limits and gaps: local run_tests.py under Node 20 gives 24 findings because the Node 24.22.1 pin guard refuses it (hosted runs on Node 24 pass).
