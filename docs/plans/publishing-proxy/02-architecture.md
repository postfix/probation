## Program behavior

Purpose: Complete npm and Python package-client workflows through one selected Probation URL per organization registry. The certificate holder's current group policy governs package reads; the upstream registry's permissions govern writes.

Capabilities: An administrator configures registries, certificate provider and Users. A project selects one registry URL. A valid certificate identifies an active member on every request. Login, publishing and account actions use that same URL and a developer token only when the upstream operation needs it. A signed-in member may obtain a Probation-issued setup bundle only when self-service is enabled.

Failures: No, invalid, revoked or foreign certificate; disabled or removed member; unavailable status or management; foreign or removed registry; unknown route; and unsafe destination all fail before package bytes or upstream I/O. Upstream write refusals remain refusals. No registry fallback occurs.

Programming entry point: TLS peer evidence enters the existing HTTP registry router as a transport-owned request extension. Registry path selects ecosystem and immutable registry ID; classification selects a guarded read, named login bootstrap or upstream-authorized action without another client URL.

## Endpoints

- Portal organization certificate settings expose provider, public CA trust and Probation self-service switch. In organization-issued mode the identity-field input in the approved screen is a validated declaration: save accepts only the URI SAN membership UUID field, regardless of its displayed draft value. The status-source input records the expected issuer OCSP AIA URL; activation tests a sample leaf and requires its embedded AIA to match that URL and operator-approved egress. Every admitted leaf must match the saved expectation; the input cannot replace a leaf's AIA or supply status by itself. The test-certificate action checks the sample leaf's field, AIA and reachable issuer status before activation. Users exposes membership, roles, groups, access changes and a selected member's Probation-issued certificate revocation. Signed-in self-service issues/downloads a setup bundle and revokes the user's own certificate. Organization-issued revocation stays in the issuer.
- Portal registry create/list/edit-trust-or-read-connection/remove uses existing administrator authorization. Registry target and ecosystem are immutable; change by remove-and-add. The registry settings also list exact HTTPS origin plus path-prefix deletion scopes, including noncanonical selected-origin paths, each extra-origin scope with a visible "send developer token" choice that defaults off; only an administrator can add, remove or change one. No wildcard, string-prefix host/path match, or redirect approval exists.
- `https://<firewall>/registry/npm/<registry-id>/...` and `https://<firewall>/registry/pypi/<registry-id>/...` are the selected organization registry URLs for reads and writes. One URL is configured in each client. Legacy `/npm/...` and `/pypi/...` reads remain separate; numeric npm package/version routes retain their old meaning. Unknown package-file or alternate read paths refuse before upstream I/O.

## Data

- Each active membership has an immutable public certificate UUID, distinct from mutable login name or email. A leaf certificate carries exactly one URI SAN for it; its chain must anchor in the selected organization's current roots. Certificate serial plus issuer identifies one certificate for targeted revocation. Org path, root and UUID must agree.
- Probation-issued certificates use protected issuer key material, unique serials and user-specific private keys generated only for the response bundle. A bundle is returned to the signed-in member with no-store headers and no log or durable plaintext copy. Per-member public certificate rows store serial, expiry and revocation, indexed for targeted lookup. Disabling self-service stops new issuance/downloads, not validation of existing certificates.
- Organization-issued mode stores public CA roots and the expected issuer OCSP AIA URL, never an issuer private key. Each admitted leaf's AIA must equal that expectation and pass operator egress policy. Admission sends a unique nonce to the leaf's AIA on each request and verifies the signed OCSP responder's issuer authorization, issuer name/key hash, presented serial, matching nonce, response time/validity and `good` status. The configured issuer must make every committed revocation visible to that responder before acknowledging the revoke. No positive status cache crosses requests; missing or mismatched AIA, malformed response and outage fail closed. Activation requires a real integration witness for this contract. This provider has per-request latency and availability cost.
- Registries have never-reused IDs. Persisted project, cache, in-flight and artifact identity includes `(registry-id, ecosystem, package)`. Links contain only selected URL and registry ID, no credential. A D40 action lease stores its exact URL sealed under a dedicated firewall data-directory key, survives a firewall restart but expires after 24 hours; an unpublish delayed beyond that lifetime fails explicitly before outbound I/O; if npm already removed the version in its preceding PUT, an administrator must finish or recover the operation at the selected upstream. Existing ambiguous rows are invalidated safely during migration.
- A token-bearing canonical npm packument body is request-local: it bypasses shared metadata caches, project persistence and in-flight coalescing. The sole durable exception is the bounded, sealed D40 action lease for a listed tarball destination, keyed by immutable registry ID, admitted member and existing reference digest and bound to npm package, version and filename. The reference digest may be shared, but the action lease is not shared between members. It contains no developer token or packument body; ordinary artifact GET/HEAD still rechecks current group policy and never uses the developer token. The next packument request reaches the selected upstream with its own token, or follows the ordinary group-filtered read path without a token. No token-private or group-hidden response enters a shared result keyed only by package.
- The firewall creates a random 256-bit action-lease encryption key in its protected data directory on first use, opens it on restart, and refuses lease creation/resolution if the key is missing or unreadable. Sealed URLs use a fresh authenticated-encryption nonce and associated registry/member/reference identity. The key is included in the firewall backup and may be rotated only after clearing or expiring leases. Raw query strings, sealed bytes and developer credentials are absent from access logs, errors and client links. Losing the key can require administrator recovery of a partial unpublish; it never causes plaintext fallback.

## Flow

1. The TLS listener optionally authenticates a client certificate at handshake, proves possession of its leaf key and preserves the complete presented chain as transport-owned evidence without treating any organization root as selected. Certificate-free browser portal sign-in still connects. Package routes require that evidence; arbitrary Host, forwarded identity or certificate headers cannot produce it. Canonical authority and registry path then select the organization registry; admission validates the preserved chain, validity and client-auth purpose against that organization's current roots on every request. Two distinct organization roots and root rotation must reject cross-organization or formerly trusted leaves at the next request.
2. Admission extracts one membership UUID from URI SAN, checks current certificate status and active member, resolves current group and policy layers, and joins the selected registry in the same organization/ecosystem. Every new request performs these checks; management/status outages refuse instead of reusing prior success. Existing network and rate controls apply. A request admitted before revocation may finish; the next request refuses.
3. The classifier admits only known protocol reads and named actions under the selected `/registry/<ecosystem>/<id>/` base. A canonical npm packument GET with a valid client certificate and developer token sends that token only to the selected upstream and may return its metadata despite group read policy; this applies to `npm view` and installs that never write as well as publish/deprecate preflights. The upstream decides whether that token can read metadata, and the bounded response body is request-local, never entering shared cache, project persistence or in-flight coalescing; D40 allows only its exact admitted tarball destination references to persist. Tokenless packument metadata, every other metadata/file read, search, audit, ping and artifact dereference use current group policy even when a token is present. Audit responses are rebuilt from visible package versions and safe advisory fields; input/output size, total lookup count, concurrency and one deadline are bounded, and unparseable or over-limit data refuses, and an upstream unsupported bulk endpoint remains an error. The exception never grants artifact bytes or authorizes a later write. A trusted registry skips only its own age delay. Named web-login start/poll alone may be tokenless; named legacy login sends the developer's Basic username/password to the selected upstream to obtain a token. Other write/account actions require a developer token and upstream permission. The shared read connection is confined to ordinary authorized reads. Package clients receive no direct-upstream links.
4. Outbound transport accepts HTTPS only. Public origins connect only to globally routable IPs; a private registry or OCSP responder requires an operator-approved exact host/port plus organization-scoped CIDR. Every DNS answer and selected connected peer is vetted and pinned while TLS validates the hostname; each redirect repeats this check. Action redirects refuse, and permitted artifact redirects carry no credential. An upstream `doneUrl` maps only an allowed same-origin poll path back to the same URL; query tokens are redacted. For version-unpublish, the selected upstream's advertised tarball URL is admitted against the canonical selected path or D41-approved origin/path scope before a sealed lease is stored; registry, member, package, filename, lease lifetime and current origin/path approval are rechecked on DELETE; no arbitrary client-supplied URL reaches transport. Unknown routes and alternate file paths refuse before outbound I/O.
5. The signed-in portal checks session membership and provider/self-service state, issues a unique certificate and streams a no-store setup bundle for npm, pip, Twine and uv. Installation writes key material/tool settings to user-local protected paths, without shell-history secrets or project-file credentials. Revoking that certificate or disabling its user prevents the next package request.

## Constraints

The existing listener has no client-certificate verifier or verified request identity; Authorization-only key admission cannot parse a certificate header. Browser portal and package paths share ingress, so browsers remain able to connect without a client certificate while package paths require one. The management key cache may serve stale success on outage; certificate admission cannot use it. Per-request enterprise status checks add latency and make issuer outages deny traffic. Certificate identity, active membership and exact selected-registry routing need wrong-value and cross-tenant runtime controls plus source review. The Rust analyzer checks selected call order but cannot establish the SQL join or same-value propagation.

## External

The organization issuer must encode the immutable membership UUID, put an OCSP AIA URL in each leaf and operate an issuer-authorized nonce-capable responder with read-after-write committed-revocation status. The operator approves exact private registry/responder hosts, ports and CIDRs per organization. Selected npm/Python registries and pinned npm, pip, Twine and uv clients are external. An npm registry must provide audit advisory data for a successful audit; Probation does not add a separate advisory service. Pinned npm 11 has no automatic quick fallback when its bulk request is unsupported. Browser web-login may open an upstream page; package-client registry traffic stays on Probation. Website-only workflows remain outside this feature.
