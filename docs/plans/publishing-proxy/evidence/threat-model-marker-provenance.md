# Threat model: active npm unpublish marker provenance

**Verdict: MODELED.** The active design identifies the relevant trust boundaries and specifies observables for the API-key/registry-credential split, all three DELETE routes, and the revision-marker lifecycle. No unresolved design contradiction remains in the reviewed documents.

## Scope and entry points

Reviewed approved product scope and active architecture, program design and slices; `molecule-flow.json`, `molecule-contracts.json`, their specs; the lead policy/API and FIX-16-A design; and the preceding active local-service threat model. The new unpublish flow models selected-upstream revision PUT, exact-removal verification, revision-bound marker commit, then marker-gated reference DELETE. The direct/whole-package flow models separate authorization outcomes. Proposed service source files do not exist and are not represented as implemented.

Actors include local package tools and CI, the shared enforcement service, policy server, selected registry, administrator-approved delete origins and local administrators. Entry points include policy snapshot retrieval; selected npm/PyPI package reads and writes; npm package revision PUT; whole-package revision DELETE; direct canonical tarball DELETE; and version-reference DELETE. Assets are the policy key and effective policy, registry credentials, hidden metadata/artifacts, registry identity, unpublish reference and marker, local state, and external registry state.

The service API key identifies/authenticates only the firewall's policy snapshot request in HTTP `Authorization`. Package-manager credentials authorize only requests to the selected registry. A shared service has no per-package-request member identity. D41 adds an exact, administrator-approved origin/path scope for version-reference DELETE; upstream authorization remains decisive for writes.

## Decisions and residual risk

No risk is accepted or transferred. The design's explicit residuals are that local/device administrators can bypass local enforcement unless existing device/network controls prevent it, and a managed outage can use matching remembered policy only within the approved C19/C20 window. No per-user identity is claimed for shared service requests.

Finite `molecule-check` PASS confirms declared flow consistency, not implementation behavior. The new source obligations are pending because service route/unpublish source is future work. The route-specific classifier and marker-after-PUT specs prove call order only; they do not prove request bytes, exact response/reference/revision binding, durable atomicity, or concurrency. Slice 1/3 runtime controls and source review remain required. No source analysis or product tests were run.
