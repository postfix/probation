# Slice 3 implementation evidence

## Delivered read path

The selected npm URL admits a live certificate and current registry/group principal before a named read. Canonical `GET /registry/npm/{registry}/{package}` with a developer Bearer token, optionally `?write=true`, uses a request-local selected-origin fetch and returns the upstream packument if upstream accepts it. It does not use the shared metadata store, cache or in-flight path. It rewrites artifact URLs to the selected firewall URL. Ordinary metadata, search and artifact reads retain group filtering; tokenless or upstream-denied token requests cannot reuse the private result. Search has one 30-second total deadline across cold packument fetches and filtering, then releases the admitted permit on timeout. Its returned objects are built only from allowed version fields in filtered packuments, with an accurate visible total; neither original upstream search fields nor denied advertised versions pass through. Named bulk/quick audit, whoami and ping use the selected origin. Unknown and ambiguous routes refuse before upstream.

### Historical audit leak red witness

The approved program design says audit retains current member/group policy. The then-current named read route bounded the response and rechecked certificate admission, but returned successful audit JSON unchanged. The previous fake returned only `{}` for bulk and an empty `vulnerabilities` object for quick, so that E2E could not detect a hidden advisory. A new nonempty fake response and selected E2E control proved that both endpoints had returned a group-hidden package name, a hidden marker in a permitted advisory title/URL and arbitrary quick metadata unchanged. The controlled red failed at `publishing-npm-read.mjs:195`; see [TDD evidence](tdd-slice-3.md). Production audit behavior was unchanged for this red witness; the approved filter and final green result are recorded below.

The pinned npm 11.21.1 image's installed `@npmcli/arborist/lib/audit-report.js` `prepareBulkData` (lines 370–384) sends `{ packageName: [installedVersion, ...] }`, with gzip; `#getReport` (lines 317–347) parses bulk JSON and has no quick call. `#init` (lines 118–124) consumes a bulk response map `{ packageName: [advisory, ...] }`. Its installed `@npmcli/metavuln-calculator/lib/advisory.js` (lines 20–47) consumes advisory `id`, `name`, `title`, `url`, `severity`, `cwe`, `cvss` and `vulnerable_versions`. The local npm 10 image's installed Arborist `audit-report.js` (lines 275–301, 323–347) shows the legacy quick response shape `{ advisories: { id: { module_name, id, title, url, severity, vulnerable_versions } } }`; it converts those entries into the bulk map. The normal fake quick response predates this inspection and is only an empty-route status probe, not a shape proof for npm 11. The adversarial quick fault uses the observed legacy shape.

Options considered before approval (C37/D39 selected the first approach):

1. Rebuild audit results from the currently filtered selected-registry packuments. For each advisory, retain only eligible versions, narrow `vulnerable_versions` to their exact version strings, and emit a minimal advisory with canonical package name, generic title, validated severity and synthetic ID. Drop arbitrary title, URL, CWE, CVSS and quick metadata because they can carry hidden facts. This was selected as the reduced response after the npm compatibility and response-bound checks were added; it preserves vulnerability detection for visible versions while omitting upstream advisory details.
2. Refuse nonempty or unparseable audit responses until a group-safe representation is agreed. This avoids disclosure but fails the approved N04 usable audit outcome.
3. Preserve upstream fields only if the selected upstream supplies a trusted group-specific audit view. That is a new integration assumption absent from the current design and fake; the firewall cannot prove arbitrary text fields contain no hidden metadata.

Request-only validation cannot close this gap: the red upstream returned extra hidden advisories and embedded hidden data in an otherwise permitted advisory. That red witness led to the approved reduced advisory design and the filter implemented below.
