# Final selected npm route threat review

Verdict: **MODELED** (design-only review, 2026-10-28).
Blocking findings: **none**. The approved product, architecture, program design, Slice 4 plan, and N05–N23 matrix account for the selected npm route boundary. Proposed source is outside this review.
Scope: selected `/registry/npm/<id>/` npm actions and adjacent reads, with certificate admission, credential handling, selected destination, whole-package and version-tarball deletion, legacy route separation, and unknown-route refusal.

## Entry points, boundaries, and assets

Actors are the certificate-bearing developer, a malicious or compromised package client, the selected upstream registry, a registry administrator approving D41 deletion scopes, the private-egress operator, the certificate issuer/status responder, and the signed-in setup user. The client can control method, path, headers, developer credential, revision JSON, and referenced package names; upstream metadata and tarball URLs are external data.

Entry points are N05–N23: web and legacy login; identity/ping; package publish, deprecate and version/whole-package unpublish; dist-tag, owner, access, team, logout, org, profile, token, star, stage and trust operations; and their named read sides. They include canonical token-bearing packument GET/`?write=true`, package PUT, revision PUT, whole-package `DELETE /<package>/-rev/<revision>`, member-bound `DELETE /artifacts/<reference>/<filename>/-rev/<revision>`, direct canonical tarball DELETE, unknown mutation/PATCH, and legacy `/npm/...` reads. N16 is the artifact-link/lockfile secret witness.

Trust boundaries are TLS peer to current member/group/registry admission; client path to disjoint legacy/read/login/action/refused classification; developer Basic or bearer credential to the selected upstream; selected upstream response to request-local metadata or a sealed action lease; accepted revision PUT to durable one-use deletion marker; administrator D41 scope to extra deletion destination; and hostname/DNS/connected peer to outbound HTTPS. Assets are upstream package and account state, developer credentials, shared read secret, certificate keys and current member status, group-hidden metadata and artifact bytes, registry identity, sealed URL/query/key and marker integrity, network authority, and firewall availability.

## Route decisions and limits

N05 is the sole tokenless web-login start/poll bootstrap. N06 is a credentialed **Basic legacy login exception**; its password is confined to the selected upstream login exchange. N07 ping and the read sides of N12–N15/N18–N23 receive named, nonmutating classification; whoami uses the developer identity credential. N08–N11 package and revision writes retain separate upstream authorization. N11 whole-package DELETE is selected-origin and upstream-authorized; only version-tarball reference DELETE uses D40/D41 lease and accepted-removal marker. N16 scans artifact links/lockfiles for secrets; N17 logout needs upstream revocation and fresh-whoami refusal. N19 profile, N20 token, N21 star/stars, N22 stage and N23 trust are explicit inventory members, including their read and mutation sides. Legacy numeric npm package/version routes remain under `/npm/...`; selected routes use `/registry/npm/<id>/`.

No accepted or transferred risk is proposed, so no risk approval or owner is needed. The design has no remaining decision blocker. The pinned-client traces, exact route values, current certificate/member join, token destination, marker atomicity, sealed-store contents and connected peer need Slice 4 runtime assertions and independent source review; structural order checks alone cannot establish those values. This review does not analyze proposed source and does not claim implementation verification.

**Omitted threats: 0.** Eight retained threats cover the in-scope boundaries.
