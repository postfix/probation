# npm 11 login, publish and package administration

Verdict: ANSWERED from npm 11.21.1 documentation and source; no live upstream probe.

- Default `npm login` uses web authentication. CLI registry requests start with `POST /-/v1/login`, and npm's public login returns a browser `loginUrl` on `www.npmjs.com`. The browser step is outside the registry origin. The CLI polls `doneUrl` via the configured registry; npm 11 tests include a canonical `registry.npmjs.org` done URL routed through a configured proxy. The returned token is saved for that configured registry. A proxy must preserve the browser URL, map the poll to its selected registry, and test the upstream-specific flow. `--auth-type=legacy` uses a registry `PUT /-/user/org.couchdb.user:<username>` where supported; npm's 404 web fallback also invokes legacy behavior.
- `npm publish` checks the selected registry's packument with GET and sends a package PUT containing metadata and tarball attachment. The publish library builds metadata tarball URLs from the configured registry.
- `npm deprecate` uses GET with `?write=true` then PUT. `npm unpublish` uses revision-aware PUT/DELETE and, for a version, a tarball DELETE derived from `dist.tarball` path. A generic GET-only proxy misses these client actions.

Primary sources: [npm login docs](https://docs.npmjs.com/cli/v11/commands/npm-login/), [public npm browser sign-in docs](https://docs.npmjs.com/accessing-npm-using-2fa/), [login command](https://github.com/npm/cli/blob/v11.21.1/lib/commands/login.js), [auth helper](https://github.com/npm/cli/blob/v11.21.1/lib/utils/auth.js), [login tests](https://github.com/npm/cli/blob/v11.21.1/test/lib/commands/login.js), [publish command](https://github.com/npm/cli/blob/v11.21.1/lib/commands/publish.js), [publish library](https://github.com/npm/cli/blob/v11.21.1/workspaces/libnpmpublish/lib/publish.js), [deprecate](https://github.com/npm/cli/blob/v11.21.1/lib/commands/deprecate.js), [unpublish command](https://github.com/npm/cli/blob/v11.21.1/lib/commands/unpublish.js), [unpublish library](https://github.com/npm/cli/blob/v11.21.1/workspaces/libnpmpublish/lib/unpublish.js).

Design implication: The package client's registry traffic can remain on its selected Probation URL, but default login includes an upstream-supplied browser destination. The approved non-goal of mirroring upstream websites leaves that browser step upstream. The acceptance matrix must assert the browser destination and keep CLI registry traffic through Probation. Public and private upstreams require separate live checks.
