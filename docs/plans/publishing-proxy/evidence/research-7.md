# Selective Artifact Keeper borrowing for the approved proxy

**Question:** Which concrete Artifact Keeper source patterns can Probation borrow selectively for its approved npm/PyPI publishing proxy and registry administration UI, and can any reduce Slice 4 code without changing approved behavior?

**Decision:** Whether the Slice 4 implementer should copy or adapt a narrow upstream algorithm now, defer one to Slice 5, or use UI ideas only. **Stopping condition:** Source-level path, behavior, test and contract comparison are sufficient; runtime interoperability is outside this review.

## Slice 4 recommendation

Use candidates **1** and **5** as focused code-review and client-probe cases. Candidate 2 is conditional on an actual nonstandard selected-upstream tarball URL. No inspected Artifact Keeper function removes a Slice 4 implementation obligation: its npm [router](https://github.com/artifact-keeper/artifact-keeper/blob/1df2003adefa274a4e0a585760580756c88b76f7/backend/src/api/handlers/npm.rs#L60-L151) has GET-only `/-/*`, no named web-login start/poll or deprecate/account write routes, and [publish stores locally after AK's own authorization](https://github.com/artifact-keeper/artifact-keeper/blob/1df2003adefa274a4e0a585760580756c88b76f7/backend/src/api/handlers/npm.rs#L6130-L6195). The handlers depend on AK `SharedState`, Postgres, storage, repository types and cache. Probation should keep its own small named-action proxy, independent developer-token forwarding and selected-origin guard.

**Do not borrow failure/cache behavior:** AK's [npm audit helper](https://github.com/artifact-keeper/artifact-keeper/blob/1df2003adefa274a4e0a585760580756c88b76f7/backend/src/api/handlers/npm.rs#L2203-L2285) turns upstream failures and non-success into empty advisory responses. Probation's C37–C38 require a reduced visible signal and preserved unsupported bulk 404; empty fallback would falsely report clean. AK's remote packument and PyPI Simple caches are service-coupled and cannot replace Probation's current per-request policy, token-private canonical packument and registry-partitioned cache rules.

**Limits:** `proxy_service.rs` is too large for the available GitHub file reader and its internal implementation was not used as evidence. The cited HTTP handlers, auth and client builder settle the selective candidates above. No Artifact Keeper runtime was executed, and no code reduction was measured.
