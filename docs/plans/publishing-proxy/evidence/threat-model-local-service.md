## Actors and entry points

- Local package-manager users and CI jobs enter through selected npm/PyPI registry URLs; workloads in cluster deployment reach the service through approved nodes. Package callers have no individual Probation identity.
- The local/shared enforcement service retrieves policy with `GET /api/v1/policy/snapshot`, sending the organization service API key only in HTTP `Authorization: Bearer <service-api-key>`.
- npm/PyPI and other package managers send their own registry credentials on package operations. Those credentials go only to the explicitly selected registry operation that needs them; the upstream decides read/write authorization.
- Other actors and inputs are the policy server, configured package registries and npm deletion origins, local administrators/configuration, OS service managers, CI runners, and approved cluster nodes.

## Assets and trust boundaries

Assets: service API key and managed policy; registry identity and policy; package-manager credentials; hidden package metadata, artifact bytes and caches; audit output; durable npm references and revision markers; configuration, local store and logs; listener availability; OS and CI secrets.

Managed policy retrieval is distinct from package traffic. The service key authenticates only the service's snapshot request and does not go to the package tool or a registry. Package-manager credentials never authenticate a local caller, fetch policy, choose a group, or authorize local policy bypass. Standalone mode is an explicit TOML configuration; managed failure never switches to standalone. Managed outage may continue only with matching remembered central policy under C19/C20; freshness follows the selected propagation interval (one minute by default). Machine access is loopback/local-machine; cluster access trusts approved nodes, not individual workloads. Existing device/network controls are relied on to prevent local bypass; the design adds no host attestation. Package-manager caches are outside network re-delivery enforcement.

## Decisions and residual risk

- No accepted or transferred threat is asserted. The design does not name an owner and explicit approval to accept any of the retained threats.
- The managed propagation interval and remembered-policy outage behavior leave a bounded exposure window. Local package-manager caches and compromise of an approved node remain outside per-user network re-delivery enforcement.
- The publication gate specifies a synchronization contract, not proof that future source obeys it. The unpublish model specifies service binding and one-winner marker behavior, not proof of transaction isolation. Source review, exact credential/header traces, cross-thread response-release tests, marker race/restart tests, and native listener/secret custody witnesses remain required in their assigned slices.
- No proposed-source analysis or tests were run. `service_registry.rs`, `service_unpublish.rs`, and runtime witnesses are absent as planned future work; prose and finite-model PASS are not implementation evidence.
