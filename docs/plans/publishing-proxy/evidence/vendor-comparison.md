# Registry publishing comparison

Checked official vendor material on 2026-10-25.

- [Socket Firewall Enterprise configuration](https://docs.socket.dev/docs/socket-firewall-enterprise-registry-mode-configuration-reference) documents two distinct credential paths. Its normal client-auth gate accepts an operator-configured shared bearer token or Basic password; after a match it strips that client Authorization, and a separate `upstream_token` can replace it. On a path route with `forward_client_auth`, the gate instead accepts any well-formed bearer token and forwards that caller token to the upstream; it does not verify the shared client-gate password or add proxy authentication, and `upstream_token` is ignored. The forwarding mode does not accept pip Basic credentials. The docs also warn about authenticated metadata caching.
- [StepSecurity Secure Registry](https://www.stepsecurity.io/blog/introducing-secure-registry-install-time-defense-for-the-npm-supply-chain) documents install-time protection and cooldown. Its published material inspected here does not establish a same-URL login/publish proxy.
- [Aikido Safe Chain](https://help.aikido.dev/code-scanning/aikido-malware-scanning) and its [source repository](https://github.com/AikidoSec/safe-chain) describe wrapping package installs and blocking malicious or new packages. The inspected material does not establish a same-URL login/publish proxy.
- [Nexus npm publishing](https://help.sonatype.com/en/publishing-npm-packages.html) publishes to a hosted repository, or to a group with an explicitly selected writable hosted repository. [Nexus npm security](https://help.sonatype.com/en/npm-security.html) has the npm client authenticate to Nexus. This is a repository manager owning the published package, rather than forwarding an individual public-registry publisher token through a security proxy.
- [JFrog Artifactory npm repositories](https://docs.jfrog.com/artifactory/docs/npm-repositories) likewise distinguish local, remote and virtual repositories; local repositories hold published internal packages and a virtual URL can include them. The client logs in to Artifactory. This does not document forwarding that same client credential to a chosen external publisher account.

Design implication: Socket demonstrates a per-route choice between a shared proxy credential and forwarding the individual's upstream credential, matching approved C4 on writes. It does not carry both credentials in one HTTP Authorization value or solve Probation's distinct user/group host access question for shared private downloads under C8.
