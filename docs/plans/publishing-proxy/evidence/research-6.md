# Artifact Keeper fit for the publishing proxy

**Question:** Can Probation reuse tested Artifact Keeper code as a small dependency or adapter at its current proxy seam, or is running Artifact Keeper as a separate selected upstream the practical reuse?

**Decision affected:** Whether Slices 4–5 should depend on Artifact Keeper code or use it as a selected upstream while preserving Probation's approved certificate, current group policy, one-URL routing, developer-token authorization, selected-origin egress and transparent responses.

**Snapshot:** `artifact-keeper/artifact-keeper` main commit [`1df2003adefa274a4e0a585760580756c88b76f7`](https://github.com/artifact-keeper/artifact-keeper/commit/1df2003adefa274a4e0a585760580756c88b76f7), committed 2026-10-28 09:29 UTC; workspace version `1.11.3` in [Cargo.toml](https://github.com/artifact-keeper/artifact-keeper/blob/1df2003adefa274a4e0a585760580756c88b76f7/Cargo.toml). Its [license](https://github.com/artifact-keeper/artifact-keeper/blob/1df2003adefa274a4e0a585760580756c88b76f7/LICENSE) is MIT, permitting reuse with the notice retained. All source observations below use this commit.

**Recommendation (inference from the cited source and approved [architecture](../02-architecture.md) / [slices](../04-slices.md)):** Do not add the Artifact Keeper backend crate to Slices 4–5 as a purported small proxy dependency. Retain Probation's existing classifier, certificate admission, policy checks, URL rewriting and selected-origin transport. If the organization chooses Artifact Keeper as the **actual selected upstream**, run its hosted registry separately and treat its own token/permissions as upstream authority; Probation still fronts it at the approved URL. This may reduce registry-operation implementation at the upstream, but does not remove Probation's named-action routing, login mapping, group-safe reads or security controls. If the selected upstream must remain some other registry, Artifact Keeper's Remote repository is a read proxy, not a way to forward writes to that registry.

**Unknowns requiring a probe:** No end-to-end witness was run for pinned npm 11.21.1 web login/legacy login, deprecate, owner/account actions or publish against hosted Artifact Keeper behind Probation, nor for pinned pip 26.2.2, Twine 7.0.0 and uv 0.13.5 through the approved one-URL mTLS facade. The smallest settling check is the plan's disposable client-shape probe against a hosted Artifact Keeper instance with two tokens (allowed/denied), capturing request methods/paths, auth, rewritten response links and any `doneUrl`/redirect. A separate probe is needed if Artifact Keeper is proposed as a remote bridge to another registry; the inspected write guards predict rejection.

**Limitations:** Source inspection establishes implementation shape, not runtime interoperability or a measured code-size reduction. No product code or approved gate was changed.
