# Selected npm mutation route threat model — corrected N05–N23 denominator

Verdict: **MODELED** (design review, 2026-10-28).
Blocking findings: **none**. Approved Gates 1–4 and the current design are present; the corrected N05–N23 denominator closes the earlier route-inventory gap.
Scope: selected `/registry/npm/<id>/` package and account mutations, their adjacent named reads and canonical packument preflights, whole-package revision DELETE, version-reference DELETE, direct canonical tarball DELETE and unknown local refusals. This is a design review, not implementation verification.

## Entry points, boundaries and assets

- **Actors:** certificate-bearing developer (including a malicious or compromised client), selected upstream registry, registry administrator approving D41 scopes, private-egress operator, certificate issuer/status responder, and signed-in setup user.
- **Entry points:** N05–N23; package PUT, revision PUT, whole-package `DELETE /<package>/-rev/<revision>`, reference `DELETE /artifacts/<reference>/<filename>/-rev/<revision>`, direct canonical tarball DELETE, canonical token-bearing packument GET and `?write=true`, named `/-/` actions and adjacent reads, unknown mutation/PATCH.
- **Boundaries:** TLS peer → current member/group/selected registry; client method/path → disjoint read/bootstrap/action/refused classification; developer token → selected upstream permission; upstream metadata → request-local response or sealed member-bound lease; revision PUT → durable one-use removal marker; D41 approval → exact extra deletion destination; selected origin → vetted DNS/connected peer/TLS. Portal session → certificate bundle is adjacent and covered by Gates 1–4.
- **Assets:** upstream package, owner, team, organization, profile, token, star, stage, trust and login state; developer bearer and shared read secret; certificate/key and current member status; group-hidden metadata and artifact bytes; selected registry identity; sealed URL/query and key; marker integrity; outbound network authority and firewall availability.

## Route denominator and decisions

- **N05–N07:** exact tokenless web-login start/poll; credentialed legacy login and whoami; certificate-guarded read-only ping. Forged `doneUrl`, unrelated tokenless action and wrong destination refuse.
- **N08–N11:** package publish, deprecate, version unpublish and whole-package unpublish preserve the selected upstream's separate read/write decisions. Version-reference DELETE uses D40/D41 and its accepted-removal marker; whole-package revision DELETE uses upstream authorization directly; canonical tarball DELETE refuses locally.
- **N12–N15 and N18–N23:** dist-tag, owner, access, team, org, profile get/set, token list/create/revoke, star/stars, stage and trust each receive exact route, destination, developer-credential or read-side classification, upstream allow/deny and local-refusal review. N20 token creation has a no-log witness. N19/N21/N23 are explicit, not covered merely by a generic `/-/` label.
- **N16–N17:** artifact URL/lockfile secret scan is adjacent read evidence; logout must reach upstream revocation under the selected account, remove the local token, and make a fresh whoami fail. A proxy success on upstream denial is forbidden.
- No accepted or transferred risk is proposed. D40/D41 apply only to version-tarball reference deletion; C4 leaves whole-package deletion to upstream permission. No new product decision is needed.

## Verification limits

SMTC CLI availability was checked; no source analysis was run because this is a design review of proposed behavior. Structural checks can show guard order, while exact route shapes, selected registry/member values, token bytes, normalized URL and connected peer, one-use atomicity, sealed contents and actual upstream decisions require Slice 4 pinned-client, store/network assertions and independent source review. Missing proposed code does not make the design verdict unknown. STRIDE and noninterference, capability/ambient authority, isolation, TOCTOU, unsafe-deserialization and complexity lenses were applied to the listed boundaries.

**Omitted threats: 0.** Eight retained rows cover the in-scope boundaries.
