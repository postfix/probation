# NORA reuse for the selected npm and Python proxy

**Decision:** Reuse NORA's proven protocol cases and small algorithms where they fit the approved selected-registry flow. Keep the current npm/Python delivery scope and the approved certificate, group, token and upstream-authority boundaries. Source reviewed at [`aa4de65`](https://github.com/getnora-io/nora/tree/aa4de65fe1a60ffd4e848406f09b810207abb845) (2026-10-27). NORA is [MIT licensed](https://github.com/getnora-io/nora/blob/aa4de65fe1a60ffd4e848406f09b810207abb845/LICENSE); retain its notice if substantial code is copied.

**Implementation consequence:** NORA does not remove a Slice 4 action requirement: the inspected npm router has GET, PUT and POST, while Probation must also map tokenless web-login, selected-origin deprecate/account writes, credential-bearing redirect refusal and publisher authorization. Its [library manifest](https://github.com/getnora-io/nora/blob/aa4de65fe1a60ffd4e848406f09b810207abb845/nora-registry/Cargo.toml) brings the registry server's storage, crypto, UI and other format dependencies with its small helpers; importing the crate to obtain one helper would grow this service and still leave the action flow. Borrow its tests and small protocol rules into the existing paths. No Gate change is needed for these narrower reuse choices; adding ecosystems or replacing the approved service would reopen Gate 1 and design.

NORA's pinned [npm compatibility table](https://github.com/getnora-io/nora/blob/aa4de65fe1a60ffd4e848406f09b810207abb845/COMPAT.md#npm) confirms the boundary: upstream pull and tarball rewriting are supported, while unpublish and search are absent, dist-tag management is partial, and proxy audit responses are forwarded verbatim. Probation's approved npm matrix requires those actions and group-safe audit output. NORA's tarball link rules include same-origin noncanonical paths such as project-specific endpoints, but its read path can consult the upstream packument; Probation's npm version-unpublish flow loses the removed version from that packument before its final DELETE. This is a concrete design limit to resolve before claiming arbitrary selected-registry version-unpublish support.

**Limits:** This is a pinned source review, not a NORA runtime interoperability claim or a measured week of savings. The current Slice 4 and complete Python matrix still need client-visible proof.

**Reopened D40 design consequence:** The same-origin noncanonical case from NORA's URL examples exposes a Probation write-path gap because npm's final version-unpublish DELETE comes after its packument PUT removed the version. The revised design uses a bounded, 24-hour registry-bound action lease for an exact upstream-advertised tarball destination on the `?write=true` preflight; it does not import NORA's handler or change the approved group/audit rules. NORA has no npm-unpublish implementation to copy. The noncanonical case remains an unverified client witness until Slice 4 is reworked.
