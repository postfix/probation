## Action compatibility limits and review inputs

The pinned npm 11.21.1 version-unpublish flow first PUTs a revised packument and then DELETEs the removed tarball. The approved D40/D41 design gives each member a bounded, 24-hour sealed lease for an exact upstream-advertised tarball URL. Canonical, same-origin noncanonical, and administrator-approved extra-origin paths pass through the selected proxy URL. The firewall restores every retained exact upstream tarball URL in the PUT, records an accepted removal against the resulting revision, and consumes that marker before the one authorized DELETE. The client never receives the signed query; the key and lease survive restart. Missing or corrupt key refuses the operation. A foreign host outside the approved scopes is refused at preflight.

NORA's pinned `npm_links.rs` recognizes same-origin tarball paths outside npm's canonical `package/-/filename` shape, including a GitLab project endpoint. The D40 lease carries the exact prior link across npm's revision PUT and later DELETE; the NORA mechanism remains a read-path comparison.

NORA's pinned `COMPAT.md` marks npm unpublish and search absent, dist-tag management partial, and audit verbatim. If a selected upstream lacks unpublish, its refusal passes through. NORA is a protocol comparison; the pinned npm 11 scenario supplies the end-to-end witness here.

Pinned npm logout removes the selected registry's `certfile` and `keyfile` settings along with `_authToken`; the installed certificate/key files remain. A subsequent tokenless npm request lacks mTLS and is refused before registry admission until the setup bundle is re-run. The action E2E re-applies the bundle after logout to isolate the next web and legacy login checks. This is a user-facing post-logout limitation for download workflows. The registry-scoped certificate configuration remains in place; placing it in npm's global settings would send the certificate to unrelated registries.

NORA review input: the existing Slice 3 npm read scenario proves gzip audit input reaches the selected upstream and hidden advisory fields are filtered. It does not by itself prove compressed audit input cannot bypass the configured request-body cap. Review Slice 3's cap+1 and gzip case together before presenting the complete security claim; no audit implementation is changed in Slice 4.
