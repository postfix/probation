## Slice interface details

### Slice 1 interfaces

Uses: Existing session, membership/group policy and one configured global npm origin. Migration `0007_registries.sql` creates the final compatible registry/provider/certificate schema once; Slice 1 seeds its one origin and uses a single-registry behavior adapter, while Slice 2 adds catalog behavior without editing this applied migration. Delivers `VerifiedPeer`, `admit_certificate`, `issue_setup_bundle`, `revoke_certificate`, `disable_member`, initial classifier and `serve_package_read` for an npm install. Optional TLS client authentication proves leaf-key possession and retains the chain; certificate-free portal connections work, while package paths require evidence. The E2E scenario exercises fake OIDC sign-in, own-bundle restriction, self-service-off with an existing certificate, install, separate same-organization member/group policies, unknown and wrong routes, revocation and multi-certificate disabled-user refusal; missing certificate and management outage cause no upstream I/O. Private keys exist only in the no-store response and user-local installed files. Seven structural source obligations for registry-ID validation, TLS peer/admission, current management lookup, member lookup before bundle rendering, revoke/disable before success and policy before metadata rendering are due. Exact member/registry SQL predicates, disabled self-service, wrong routes and next-request effects require runtime controls and source review because SMTC cannot prove the Rust value binding. Model/source rechecks use the commands above. All other package operations remain closed until their slices.

### Slice 2 interfaces

Uses: Slice 1 peer/admission and read contract plus the final applied schema. Delivers organization CA trust, per-request nonce-capable issuer-authorized OCSP, current member UUID mapping, registry catalog and registry-partitioned persistence. Settings save rejects an identity selector other than URI SAN membership UUID; activation and every admission reject a leaf AIA different from the saved issuer-status expectation. The fake issuer commits revocation then the very next npm read/action request refuses; wrong issuer, serial, nonce, replay, unavailable, unknown and unverifiable status refuses. A real selected issuer must demonstrate read-after-write status before activation. Two organizations with different roots, root rotation on an existing connection, and a certificate-free portal prove the two-stage TLS contract. Private registry and OCSP origins require operator-approved exact host/port and CIDR; DNS answers, connected peers and redirect hops are tested, with TLS hostname validation. A valid certificate from another organization cannot select this registry. Registry target/ecosystem edits refuse; remove-readd uses a new ID and refuses the old ID and artifact reference. The X01/X03 plus N02 collision witness warms trusted registry A with a too-new version, then untrusted B must still apply its own age refusal before and after restart and after A is removed and re-added. Old unscoped cache rows invalidate safely, while a Slice-1 database upgrades and an existing compatible install survives restart. The Slice 2 `live-status-before-grant` and `registry-identity-before-state-use` obligations are due; the Slice 1 active-member/registry SQL join is rechecked through wrong-value runtime controls and source review. The new registry-state spec checks guard order only; exact keys, old-reference refusal, migration and restart require source review and X01/X03/N02 runtime witnesses. The old single-origin behavior adapter is removed.

### Slice 3 interfaces

Uses: Slice 2 selected-registry principal and scoped store. Extends `classify_registry_request` and `serve_package_read` to named npm reads. Only a canonical npm packument GET under `/registry/npm/<id>/` with a developer token may return selected-upstream metadata despite group policy, including `npm view` with no later write; upstream token denial remains denial. Its body bypasses shared metadata caches, project persistence and in-flight coalescing; D40 permits only a bounded set of exact tarball destination references. Tokenless metadata, other reads and all artifact GET/HEAD requests apply current certificate and group policy. The two-client check uses token A accepted for a hidden and upstream-private packument, then tokenless and denied-token B sequentially, concurrently and after restart; B never receives A-only metadata or hidden artifact bytes. Bulk and quick audit responses are reconstructed from currently visible package versions and vetted advisory fields; hidden upstream text and links cannot pass through. Malformed, incomplete or M+1 advisory data refuses, and upstream fetch/filter/render work shares a 30-second deadline with at most 1,024 distinct advisory-package visibility lookups total and 16 concurrent lookups; the 1,025th lookup makes no upstream call and returns an error, as does timeout, never clean. Unsupported upstream bulk remains an npm error. The legacy `/npm/123/1.0.0` and tarball paths retain their old meaning. Unknown/ambiguous selected routes refuse before upstream. The `audit-policy-safe` model flow requires safe nonempty output, malformed/incomplete and over-limit errors, and preserved unsupported-bulk error; N04 bulk/quick exact-byte, real npm 11, cap+1 call/permit and independent security source review prove its premises. The `audit-filter-before-render` spec/control on `src/http/audit_filter.rs::filter_audit_response` currently PASS; they establish call order only, while exact filtered bytes and error behavior remain runtime/security checks. Source obligations for classification, admission, exact canonical-token guard and policy-before-bytes on ordinary reads are due; wrong-peer/member/registry and no-shared-result runtime controls remain mandatory. Run `bounded-upstream-response` (M+1 metadata → 502 before client body; A+1 artifact → no complete file), `bounded-headers` (64 KiB+1 → 431 before lookup), `bounded-slow-response` (30-second idle/15-minute lifetime releases permit) and `bounded-redirects` (sixth artifact hop refused with no secret escape). npm actions stay closed until Slice 4.

Slice 3 recheck after D40: the token packument body still never persists or coalesces. Slice 4 owns the `?write=true` action leases, including the token-packument, store and reference changes; the N11 pinned-client shape probe must complete before that work. A commit failure or 20,000 per-member / 100,000 per-registry / 1,000,000 global live-lease quota must fail the response before any new URL is advertised; normal artifact rows are not evicted. Identical references deduplicate only for the same member; two members with the same local reference ID have separate leases. Recheck the two-client sequential/concurrent/restart test against this narrow state: token B sees no A-only metadata or artifact bytes, and a removed/re-added registry cannot resolve the old reference. Include same-origin noncanonical, approved extra-origin, unapproved foreign-host, userinfo and query-bearing URL cases based on NORA's URL-boundary examples.

### Slice 4 interfaces

Uses: Slice 3 canonical packument and guarded other reads, classifier and selected origin. Delivers named tokenless web-login start/poll, authenticated publish/account actions and same-URL response mapping. npm publish/deprecate preflight is a canonical packument GET already provided by Slice 3: the developer token goes only to the selected upstream, may reveal group-hidden metadata and cannot grant artifact bytes or the later write. Each write separately requires the upstream's permission. Credential-bearing redirects refuse. Source obligations for publisher guard and selected origin are due. The pre-Slice-1 pinned-client trace defines the exact preflight method/path/query; Slice 4 repeats it with shared-read credential denial, group-hidden owner deprecate, denied publisher, wrong origin and secret-sentinel cases. A contradiction to approved one-URL/canonical-packument behavior reopens design. Run `bounded-publish-upload` (declared B+1 → 413 before upstream; chunked B+1 → no completed write and bounded memory), action M+1 response, header/slow/redirect reruns and `bounded-login-rate` (121st start/poll in one minute → 429 before upstream). Python actions stay closed until Slice 5.

Rework after D40: pinned npm 11 must remove one version by PUT followed by DELETE through the selected URL when the listed tarball is canonical and when it is a same-origin noncanonical path or an administrator-approved extra origin, including after a firewall restart between those requests and before the 24-hour lease expires. Verify that a deprecate or unpublish revision PUT restores every leased version's exact upstream tarball URL, rejects changed HTTPS host and changed same-origin URLs for a leased version before upstream PUT while preserving a valid ordinary URL for an unleased version, and rejects a client-inserted local link without a lease; M+1 input/rendered output, nonidentity encoding, 129-level JSON, `max_references_per_project`+1 versions and timeout all refuse before upstream write; forged or expired local references refuse, and that the DELETE uses the exact old advertised URL plus the valid revision, does not fetch the now-removed version again, and that an invalid ID, cross-registry ID, changed registry/extra-origin or path-scope approval, filename mismatch, malformed revision, expired lease, unapproved foreign host, userinfo, encoded dot/slash traversal, backslash or empty-segment traversal, or redirect makes no outbound request. Approved query-bearing URLs keep their query sealed at rest under a restart-stable data-directory key, absent from client/log output, and present only on the vetted DELETE destination. Missing/corrupt key refuses leases without plaintext fallback; backup/restore and key-loss cases are exercised. Direct canonical tarball DELETE with a valid developer bearer must refuse before outbound I/O; every version-unpublish DELETE requires a recorded successful upstream-authorized revision PUT that removed that exact leased version; denied and unchanged-version PUTs create no marker, and marker-commit or resulting-revision verification failure after an accepted PUT returns uncertain partial write rather than success. The marker binds the resulting revision from PUT response or an immediate authenticated refetch; wrong-revision, concurrent and replayed extra-origin DELETEs make zero outbound calls after the first authorized attempt. Bearer is absent unless the admin explicitly enabled it for that exact origin/path scope. Verify two-member same-URL concurrent preflights and independent DELETE authorization, plus URL length 2 KiB+1 and quota+1 failures using a disk-backed seeded-store fixture with a low test cap through the same production quota code and unchanged row-count assertions without a dead link or store growth. Upstream-denied DELETE remains denied; no test may treat a proxy failure as upstream incompatibility. Source review and a defect control must establish the reference lookup before action send; client and security witnesses establish exact destination and credential confinement. Separately, exercise whole-package revision DELETE with upstream permission and upstream denial on the selected URL, confirm the developer bearer reaches only that selected registry, and review every N05–N23 route in the client-operation matrix for selected destination, developer credential or tokenless bootstrap, upstream allow/deny and local refusal as applicable, including profile, star, trust, logout, unknown catchall and PATCH refusal; whole-package DELETE is not a version-tarball marker operation.

### Slice 5 interfaces

Uses: Slices 1-4 peer, group, registry, read/action and transport contracts. Delivers Python Simple metadata/files, Twine upload, uv project/local certificate setup and generated-file scans under `/registry/pypi/<id>/`; legacy `/pypi/...` paths remain separate. Run P01-P05/U01-U02 and then every row of the fixed matrix, including both providers, the explicit X09-X11 outcomes for Probation self-service enabled/disabled and organization-issued modes, fake-SSO path, issuer revocation next request, 10,000 clients and zero direct package-client upstream/CDN connections. Repeat upload/response/header/slow/redirect bounds for Python. All due source obligations rerun; new Python-specific critical invariant gets selected spec/control or explicitly reviewed runtime evidence before completion.

## Prerequisites and checks

1. Before any Slice 1 product-code edit, run disposable one-URL request-shape probes with pinned npm 11.21.1 (mTLS install, token-bearing `npm view` without a write, web-login start/browser URL/poll, legacy login, publish/deprecate preflight, and N11 canonical, same-origin noncanonical, and extra-origin/query version-unpublish GET `?write=true` → revision PUT → second GET → tarball DELETE including the outgoing PUT body, selected client path, and whether npm preserves the advertised host/query) and pinned pip 26.2.2, Twine 7.0.0 and uv 0.13.5 (certificate setup and expected request paths). The N11 probe runs before Slice 3 or 4 D40 implementation. The fake selected registry must deny the shared read credential for npm write preflight while accepting the developer token; it must return a group-hidden packument to an upstream-authorized owner, permit deprecate with that owner token and deny the artifact and an upstream-denied write. Record exact method/path/query, TLS handshake, authentication choice, generated files and client egress in `evidence/client-shape-probe.md`; do not mutate a real registry. These probes validate the design's client assumptions, not the later full integration witness. If any selected one-URL/certificate/credential guarantee fails, reopen the design before implementation. The old [two-route probe](evidence/npm-two-route-probe.md) describes superseded URLs and is not acceptance evidence.
2. Pin npm 11.21.1, pip 26.2.2, Twine 7.0.0 and uv 0.13.5 in disk-backed client images. Verify Docker daemon and installed tools before each relevant slice. A version change requires matrix review. Remove temporary credentials/projects after scans.
3. For each scenario, confirm `--list` selects exactly its ID, run it red against pre-change product behavior, implement, then run green. `test -f` prevents absent-file false success. The full matrix must fail on a missing or skipped row.
4. Client containers reach only Probation ingress. Fake registries, issuer status, storage and management are on a backend network joined by Probation, not clients. Assert zero direct client upstream/CDN connections and record browser navigation separately.
5. Organization-issued activation requires a real issuer integration witness for the synchronous committed-revocation contract. A fake issuer establishes code behavior, not a particular enterprise issuer's consistency. The user must be shown this operational prerequisite in the design review.
