Package access certificates

Each client certificate identifies its user. Everyone uses the same organisation registry address; the user's group policy follows their certificate identity.

Certificate settings saved. Existing certificates remain valid until revoked or expired.

Probation-issued certificates

When enabled, a signed-in user downloads a command-line setup bundle with a certificate bound to their account. Running it configures Node and Python package tools for the organisation registry. When disabled, no new bundles are issued. Existing certificates continue until revoked or expired.

Organization-issued certificates

These verify client certificates issued by your authority, including a self-signed root. Keep CA private keys in your own system.

The source must reflect revocations before the next registry request. If current status cannot be verified, Probation refuses access.

Probation verifies the certificate and maps its user ID to an active member and their group policy. Company and group administrators manage those policies.
