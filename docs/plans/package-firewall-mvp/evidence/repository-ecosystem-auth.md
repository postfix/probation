## Decisive evidence

1. **“SSL auth” includes package-client certificates.** `src/lib.rs:365` loads the configured server certificate/key and installs `PeerAcceptor`. `src/managed/certificates.rs:35` configures an optional client-certificate handshake: absence of a certificate can complete TLS, and the handshake verifies the presented leaf's signature/key possession. It deliberately defers organisation trust/status to request admission; it is not a globally trusted-CA handshake. The acceptor captures the TLS chain as `VerifiedPeer`, rather than trusting an HTTP certificate header. `src/http/registry_read.rs:25` and its PyPI/recheck equivalents require that peer, ready managed state and healthy storage, then ask management on each selected-registry request. Missing peer means unauthenticated. Thus selected npm and PyPI metadata, artifact, upload and action paths use certificate identity; organisation-issued certificates are an alternative issuer, not an opt-in switch for requiring certificates.

2. **Identity and upstream credentials have distinct purposes.** `src/managed/mod.rs:154` sends registry ID, ecosystem and peer chain to management, resolves its returned platform→organisation→optional group→user layers, and applies the network/rate rules. `crates/probation-server/src/sync.rs:377` selects the requested organisation registry/ecosystem and an active member. Probation-issued admission checks registered leaf fingerprint, serial, expiry/revocation, active root and exact `urn:probation:member:{uuid}` SAN identity. Organisation-issued admission checks the member identity, active organisation root/client chain and exact saved OCSP URI; `src/managed/enterprise_certificate.rs:47` additionally requires live signed good OCSP status. For selected URLs the developer's npm bearer or Python Basic/bearer credential is upstream authority, not the firewall identity. The separate legacy `/npm` and `/pypi` managed path still calls `Managed::authenticate` (`src/http/mod.rs:149`): it extracts a `prb_` key from bearer or Basic password, hashes it and uses the managed key cache/lookup (`src/managed/mod.rs:416,1130`). Standalone legacy reads have their existing local-policy path.

3. **The management link is not package-client mTLS.** `src/managed/client.rs:46,89` builds a normal reqwest TLS client with no redirects/environment proxy and sends `bearer_auth(firewall_token)`. `crates/probation-server/src/sync.rs:210` authenticates a live `fwt_` bearer hash, firewall status, allowed source CIDRs and rate. This inspected client/server path does not configure a firewall client-certificate identity. Management TLS/edge deployment must not be described as existing firewall-management mTLS based on the package-client certificate code. External TLS termination was not inventoried.

4. **Both metadata and artifacts are protected, with one explicit npm metadata exception.** The explicit router is `src/http/mod.rs:49`. Selected npm artifact preparation and pre-response recheck appear in `src/http/registry_routes.rs:111,130`; selected Python metadata/artifacts/uploads appear in `src/http/pypi_routes.rs:243,303,330`. Rechecks compare current policy/target/trust/private-egress/read-credential context before response. Canonical npm packument GET with a certificate and developer bearer deliberately uses `token_packument` and may expose upstream metadata despite group read policy; tokenless metadata, other reads and artifacts remain filtered. Upstream request builders do not generally clone downstream headers. There are explicit credential channels: selected shared read authorization, named actions, Python upload and canonical token packument. `src/upstream/reqwest_transport.rs:243,290` attaches the shared read credential to initial metadata/artifact requests; credentialed artifact redirects consume it once. `src/http/registry_action.rs:209` admits named npm actions and permitted Basic login/bearer credentials. The transport module's older broad “no client header” prose is narrower than these current implementations, so it is not a blanket credential-stripping guarantee.

5. **The certificate contract belongs to an adjacent approved feature.** `docs/plans/publishing-proxy/01-product.md` C21–C31, especially C29–C31, require unique client certificate→active user→current group policy, Probation self-service or organisation issuer, and one selected registry URL for reads/writes. C35 explicitly permits the canonical npm token-packument exception. Its success metric requires refusal without a valid certificate even with a developer token, revocation/disablement on the next request, both certificate providers, and no private keys/tokens in project files. Expanding the five older plans must preserve this contract or explicitly reopen it. The five scope amendments are pending approval; this note approves no implementation or replacement identity mechanism.
