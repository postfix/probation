Delivered

The firewall now works for real. Before, we had tests against fake registries. Now the real npm and pip tools install packages through a running firewall, and the firewall ships as a container.

  • Real installs. npm 12.0.2 and npm 10.9.9, and pip 26.2.1 and pip 25.0.1, each install through a running instance. Pinned old and new versions mean the test does not drift as "latest" changes.
  • Container image. It builds, and its configuration check passes from inside the image. It also carries the certificate roots it needs to talk to the real registry over TLS (the secure connection).
  • Operations notes and README. docs/operations.md and README.md tell an operator how to run it, back it up, and what the limits are.
  • Benchmarks. Speed tests ran against the targets in SPEC section 12, and the numbers are recorded in docs/operations.md.

The "before" and "after" for a caller: before, nobody had shown a real npm install or pip install working through the firewall. After, that is shown, and the speed targets are measured on the final code.

The benchmark took three rounds to make honest. Round 1 looked fine, but the review found the test measured the firewall warm and the comparison cold, which is unfair. Round 3 alternated the two in one loop and took more samples. It then gave a steady result of about 110 percent against the 85 percent floor. The record says this 110 percent is a constant, not noise. The firewall reads ahead of the client and the comparison does not, which favours the firewall. It is named in docs/operations.md and was left uncorrected on purpose.

Limits

  • Test counts are from a debug build. The recorded status says the host was busy (about 200 percent CPU, swap exhausted) during benchmarks.
  • The test suite has never been green in a release build. One timing test, artifacts_concurrency::blocklist_commit_is_not_delayed_by_a_large_project_refresh, fails there. It was already failing before this work and was deliberately not fixed.
  • The repository has no -D warnings gate of its own. A warning-level regression compiles cleanly under plain cargo clippy. Both items are listed as known gaps in docs/operations.md.
  • A firewall for registries cannot reach a package that is already installed. This is the boundary of the product, and the operations notes say so.
  • Not covered by this slice: the shared service (the common policy server), the other seven package families (Maven, Go modules, Cargo, NuGet, RubyGems, Conan, Docker/OCI), and the native operating-system and cluster lanes. These belong to later slices.
